## 2. Theme input (config files, environment, INI grammar, how settings reach a client)

### 2a. Open flags and file names
- KCF2.1 (kconfig) `OpenFlag` values: `IncludeGlobals = 0x01` (blend kdeglobals), `CascadeConfig = 0x02` (cascade to system-wide files), `SimpleConfig = 0x00` (one file), `NoCascade = IncludeGlobals`, `NoGlobals = CascadeConfig`, `FullConfig = IncludeGlobals | CascadeConfig`. `refs/kconfig/src/core/kconfig.h:86-100`.
- KCF2.2 (kconfig) Constructor with a name and no path: `KConfig(file, mode, resourceType)`. Overloads at `refs/kconfig/src/core/kconfig.cpp:254`, `:263` (QIODevice), `:276` (named backend). - KCF2.3 (kconfig) Empty name with `CascadeConfig` (default app config): the name is `KConfig::mainConfigName()`. That function returns, in order: the value after `--config` in the application arguments; `globalMainConfigName` if set by `setMainConfigName`; otherwise `QCoreApplication::applicationName() + "rc"`. `refs/kconfig/src/core/kconfig.cpp:636-658`.
- KCF2.4 (kconfig) Relative name resolution in `changeFileName`: with an empty name and `CascadeConfig`, the file is `writableLocation(resourceType)/mainConfigName()`. With an empty name and `IncludeGlobals` only, the file is the global `kdeglobals`. Otherwise the config is anonymous and becomes `SimpleConfig`. `refs/kconfig/src/core/kconfig.cpp:660-694`.
- KCF2.5 (kconfig) Relative name in other cases: file is `QStandardPaths::writableLocation(resourceType) + "/" + fileName`. Absolute names are canonicalised with `QFileInfo::canonicalFilePath()`. `refs/kconfig/src/core/kconfig.cpp:680-690`.
- KCF2.6 (kconfig) `bSuppressGlobal` is true when the opened file is the global `kdeglobals` itself, which disables the global-file cascade for that object. `refs/kconfig/src/core/kconfig.cpp:690`.
- KCF2.7 (kconfig) The global file name is `kdeglobals` under `GenericConfigLocation`, held in `sGlobalFileName`, and recomputed when test mode toggles. `refs/kconfig/src/core/kconfig.cpp:57`, `:110-114`.
- KCF2.8 (kconfig) Global file discovery: `QStandardPaths::locateAll(GenericConfigLocation, "kdeglobals")` and `... "system.kdeglobals"`. The writable copy is the first entry if it lies under the user config location. `refs/kconfig/src/core/kconfig.cpp:747-754`, `:742-745`.
- KCF2.9 (kconfig) System-wide global list (least specific first): `/etc/kde5rc` (if readable and `KDE_SKIP_KDERC` is not set), then the non-writable `system.kdeglobals` copies, then the non-writable `kdeglobals` copies, each in reverse search order. The user-writable `system.kdeglobals` and `kdeglobals` are appended to the user global list, `system.kdeglobals` first. `refs/kconfig/src/core/kconfig.cpp:747-781`, `:762`.
- KCF2.10 (kconfig) `/etc/kde5rc` is the path, with the name kept in KF6 code. Windows uses `WINDIR/kde5rc`. `KDE_SKIP_KDERC` (any value set) disables it, and the comment says "for unit tests". `refs/kconfig/src/core/kconfig.cpp:116-127`, `:118`.
- KCF2.11 (kconfig) Windows only: `parseWindowsDefaults` reads the registry key `organizationName/<fileName without rc>` into the entry map when the name is not absolute. `refs/kconfig/src/core/kconfig.cpp:857-865`.
- KCF2.12 (kconfig) Config load order in `reparseConfiguration`, documented in code as "from the least to the most specific": (1) global system files (`parseGlobalSystemFiles`, if `IncludeGlobals`), (2) system app files (`parseSystemConfigFiles`, if `CascadeConfig`), (3) Windows registry defaults (Windows only), (4) global user files (`parseGlobalUserFiles`, unless the system global file was immutable), (5) the user's own file (`parseUserConfigFiles`, always). `refs/kconfig/src/core/kconfig.cpp:697-739`.
- KCF2.13 (kconfig) System app files: `QStandardPaths::locateAll(resourceType, fileName)`. The user-writable first entry is dropped when it is under the writable location. Each remaining path is prepended to the list, which reverses the search order so the least specific file parses first. A Qt resource `:/kconfig/<fileName>` is prepended if it exists. Parsed with `ParseDefaults | ParseExpansions`. `refs/kconfig/src/core/kconfig.cpp:867-901`, `:878`.
- KCF2.14 (kconfig) The user's own file is parsed last with `ParseExpansions` only, which means default-group and `$e` processing as the flags set. For `CascadeConfig` with a relative name, the user-side file is found with `QStandardPaths::locate(resourceType, fileName)` and only counted if it is under the writable location. `refs/kconfig/src/core/kconfig.cpp:903-959`, `:923`.
- KCF2.15 (kconfig) The code never reads `XDG_CONFIG_HOME` or `XDG_CONFIG_DIRS` directly. Both are resolved inside `QStandardPaths`, which is Qt code outside this tree (UNVERIFIED: the exact precedence for `XDG_CONFIG_DIRS` is not traced here). `refs/kconfig/src/core/kconfig.cpp` (no `XDG` token found in the file).
- KCF2.16 (kconfig) `KDEHOME` is not referenced anywhere in either repository (ripgrep for `KDEHOME` and `KDE_HOME` returns no hits). The one related variable is `KDE_HOME_READONLY`, see KCF2.22.
- KCF2.17 (kconfig) `KDE_SKIP_KDERC` (see KCF2.10). `KDE_HOME_READONLY` (see KCF2.22). No other environment variables are read by KConfig in `src/core/` besides the locale and `QT_*_HOME` expansion fallback (KCF2.20).

### 2c. INI file grammar (KConfigIniBackend)
- KCF2.23 (kconfig) Parsing starts with `parseConfig(locale, entryMap, options)`. An empty file returns OK immediately. `refs/kconfig/src/core/kconfigini.cpp:42`, `:57-58`.
- KCF2.24 (kconfig) Lines are trimmed. Empty lines and lines whose first character is `#` are skipped. `refs/kconfig/src/core/kconfigini.cpp:104`, `:107-110`.
- KCF2.25 (kconfig) A line whose first character is `[` is a group header. Several bracketed names on one line (`[A][B]`) nest; the parser joins the parts with the byte `\x1d`. `refs/kconfig/src/core/kconfigini.cpp:112`, `:143`. Writing does the reverse split on `\x1d`. `refs/kconfig/src/core/kconfigini.cpp:326`.
- KCF2.26 (kconfig) A group header with `[$i]` makes the group immutable (`groupOptionImmutable`). `[$i]` as the first header before any group makes the whole file immutable. `refs/kconfig/src/core/kconfigini.cpp:140-141` (group-level flag set in the header loop; the file-level flag is set in the same branch on an empty group name), `:295` (file immutability returned).
- KCF2.27 (kconfig) Any other line is a key=value pair. The first `=` splits key and value; key and value are trimmed. A line with no `=` is an error ("missing '='") unless it was a `[$d]` deletion. `refs/kconfig/src/core/kconfigini.cpp:170-178`, `:239`.
- KCF2.28 (kconfig) Key suffixes are bracketed and parsed from the right (`lastIndexOf('[')`). A bracket starting with `$` is an option list: `i` = immutable (suppressed when `kde_kiosk_exception`), `e` = expand environment (only when the parse options include `ParseExpansions`), `d` = deleted entry (with `ParseDefaults`, also marks it default). Any other bracket is a locale. `refs/kconfig/src/core/kconfigini.cpp:192-219`, `:202-214`.
- KCF2.29 (kconfig) A locale suffix is kept only when it equals the current locale or the current language (before `_`), or is `C` when the current locale is `en_US`. Other locales are skipped, or kept as a raw key when merging. `refs/kconfig/src/core/kconfigini.cpp:221-248`, `:243-246`. A localised entry sets `EntryLocalized` (and `EntryLocalizedCountry` if the locale has `_`). `refs/kconfig/src/core/kconfigini.cpp:260-266`.
- KCF2.30 (kconfig) `kde_kiosk_exception` is a global flag (default false) that disables immutability (`i`) when set. `refs/kconfig/src/core/kconfigini.cpp:20`.
- KCF2.31 (kconfig) Parsing stops for an immutable file (`ParseImmutable`) and the caller ignores later files. A parse error count above 100 (`MAX_ERRORS`) aborts the file with `ParseOpenError`. `refs/kconfig/src/core/kconfigini.cpp:76`, `:87`, `:285`, `:295`; `refs/kconfig/src/core/kconfig.cpp:896-897`, `:939-956` (parse loop breaks on `bFileImmutable`).
- KCF2.32 (kconfig) Value escaping on read (`printableToString`): a value with no backslash is returned unchanged. The recognised escapes are: `\s` (space), `\t`, `\n`, `\r`, `\\`, `\;` and `\,` (kept as two characters, for desktop-file compatibility), and `\xHH` (two hex digits, a byte). Any other escape is a warning "Invalid escape sequence" and the parse reports an error. `refs/kconfig/src/core/kconfigini.cpp:742-809`, `:744`, `:764`, `:767`, `:770`, `:773`, `:776`, `:779-789`, `:791`, `:802`.
- KCF2.33 (kconfig) Value escaping on write (`stringToPrintable`, type `GroupString`, `KeyString` or `ValueString`): leading space becomes `\s` (not for group names), `\n`, `\t`, `\r`, `\\` for backslash; `=` is escaped as `\xHH` in keys (`doEscape`) and kept literal in values and groups; `[` and `]` are kept literal in values but escaped in keys and groups; control bytes (below 32) are escaped as `\xHH`; in values, bytes 127 and above are escaped as `\xHH`; invalid UTF-8 bytes are escaped with `escapeByte`; a trailing space becomes `\s` (not for group names). `refs/kconfig/src/core/kconfigini.cpp:628-716`, `:642-646` (leading space), `:658-666` (control and high bytes), `:681-684` (backslash), `:685-690` (`=`), `:691-699` (`[` and `]`), `:710-713` (trailing space).
- KCF2.34 (kconfig) `escapeByte` writes `\x` followed by two lowercase hex digits. `refs/kconfig/src/core/kconfigini.cpp:524-533`. Key and value enumeration is in `writeEntries`, using `stringToPrintable` for the group name (`:343`, `:351`), key (`:363`) and value (`:388`). `refs/kconfig/src/core/kconfigini.cpp:298-393`.
- KCF2.35 (kconfig) Key and group names are not escaped on the `[`-line beyond what `printableToString` does; group names use `GroupString` (no leading-space protection, no `=` escaping). `refs/kconfig/src/core/kconfigini.cpp:628`, `:686`.
- KCF2.36 (kconfig) Writing a file: `KConfig::sync()` writes only when at least one entry is dirty, writing the global file for global entries and the local file for others. `refs/kconfig/src/core/kconfig.cpp:434-523`, `:466-473`.
- KCF2.37 (kconfig) Environment expansion in values (`expandString`): `$NAME` and `${NAME}` are replaced by the environment variable. `$$` is not expanded. An unset variable becomes empty, except `QT_DATA_HOME`, `QT_CONFIG_HOME` and `QT_CACHE_HOME`, which resolve to the matching `QStandardPaths` location when the env var is empty. `refs/kconfig/src/core/kconfig.cpp:193-240` (variable lookup and fallbacks inside this range).
- KCF2.38 (kconfig) Locale of a key for lookup: a localised entry (current locale) shadows the non-localised entry; the localised form follows the non-localised form in the map. `refs/kconfig/docs/DESIGN.kconfig:19-25`. Entries for the current locale are stored with `bLocal` (`refs/kconfig/src/core/kconfigdata_p.h:104`).

## 3. Colour and style model (value types, colour serialisation, key types)

### 3a. Key types and KConfigGroup serialisation
- KCF3.1 (kconfig) `QColor` is stored as a comma list of decimal integers `r,g,b` or `r,g,b,a`; the alpha component is written only when it is not 255. `refs/kconfig/src/gui/kconfiggroupgui.cpp:131-150` (writer; alpha check and list build at `:134-148`).
- KCF3.2 (kconfig) Reading a `QColor` (GUI hook): an empty value or the literal `invalid` gives an invalid `QColor()`. A value starting with `#` or containing no comma is parsed with `QColor::fromString` (for example `#rrggbb`, or a colour name). A comma value must have 3 or 4 integer fields. Each field must parse as int and lie in 0..255, else it returns the default (red, green, blue, alpha are the named components in the error message). Alpha is applied only when a 4th field exists. `refs/kconfig/src/gui/kconfiggroupgui.cpp:36-84`.
- KCF3.3 (kconfig) The `QColor` read and write hooks are installed into the core by `_kde_internal_KConfigGroupGui.readEntryGui` and `writeEntryGui` at `refs/kconfig/src/gui/kconfiggroupgui.cpp:198-199`. The hook struct is in `refs/kconfig/src/core/kconfiggroup_p.h:16-24`. Without the GUI module, QColor values are not converted (UNVERIFIED: not traced beyond the hook declaration).
- KCF3.4 (kconfig) Boolean read: a stored value is `true` unless it equals (case-insensitive) one of `false`, `no`, `off`, `0`. `refs/kconfig/src/core/kconfiggroup.cpp:249-255`. The handling of an empty stored value is not traced here (UNVERIFIED).
- KCF3.5 (kconfig) Lists: items are joined with `,`; a literal `,` or `\` inside an item is escaped with `\`. An empty list is written as `\0` when the joined result is empty (a list holding one empty string). `refs/kconfig/src/core/kconfiggroup.cpp:133-159` (`serializeList`; `\0` at `:154-157`).
- KCF3.6 (kconfig) List read: an empty value is an empty list; `\0` is a list with one empty string; otherwise `\` escapes the next character and `,` separates items. `refs/kconfig/src/core/kconfiggroup.cpp:161-185` (empty and `\0` checks at `:163-168`).
- KCF3.7 (kconfig) Integer-list read (`asIntList`) splits on `,` and converts each piece with `toInt`. `refs/kconfig/src/core/kconfiggroup.cpp:187-199`.
- KCF3.8 (kconfig) Enum values are stored as their `int` value (`ItemEnum : ItemInt`). `refs/kconfig/src/core/kcoreconfigskeleton.h:797`.
- KCF3.9 (kconfig) Font values are stored as a string (`QFont` from a `QString`; `readEntryGui` for QFont at `refs/kconfig/src/gui/kconfiggroupgui.cpp:97-99` (read), `:153-154` (write)). Other types have skeleton item classes: `ItemFont` (`refs/kconfig/src/gui/kconfigskeleton.h:54`), `ItemRect`, `ItemRectF`, `ItemPoint`, `ItemSize`, `ItemDateTime`, `ItemTime`, `ItemStringList`, `ItemUrlList`, `ItemIntList` (`refs/kconfig/src/core/kcoreconfigskeleton.h:1019-1259`).

## 4. Architecture (classes, watching and notifications, startup)

### 4a. Core classes
- KCF4.1 (kconfig) `KConfig` is the base class; `KConfigPrivate` (`src/core/kconfig_p.h`) holds the entry map, backend, open flags and the cascade logic. Key methods: `wantGlobals()` (IncludeGlobals and not `bSuppressGlobal`), `wantDefaults()` (CascadeConfig). `refs/kconfig/src/core/kconfig_p.h:99-106`.
- KCF4.2 (kconfig) `KSharedConfig` derives from `KConfig`; it registers each instance in a per-thread list and removes it in the destructor. `refs/kconfig/src/core/ksharedconfig.cpp:185-195`.
- KCF4.3 (kconfig) `KConfigGroup` is a view of one group of a `KConfig`; `readEntry`, `writeEntry`, `deleteEntry`, `hasKey` and related calls. Overloads for `QStringList` at `refs/kconfig/src/core/kconfiggroup.cpp:669-681`; list write at `:848-863`.
- KCF4.4 (kconfig) `KConfigIniBackend` implements the INI parser and writer, with a device interface (`KConfigIniBackendPathDevice`) to read a path. `refs/kconfig/src/core/kconfigini.cpp:32-42`, `:298`, `:410`.
- KCF4.5 (kconfig) `KEntryMap` and `KEntryKey` store entries sorted by group, then key, then locale (`refs/kconfig/docs/DESIGN.kconfig:7-25`). `KEntryKey` fields: `mGroup`, `mKey`, `bLocal`, `bGlobal`, `bImmutable` (`refs/kconfig/src/core/kconfigdata_p.h:82-86` comparator).
- KCF4.6 (kconfig) `KConfigSkeletonItem` (abstract, `readConfig`) and the typed `ItemX` classes in `KCoreConfigSkeleton` (`refs/kconfig/src/core/kcoreconfigskeleton.h:42`, `:170`, `:552-1259`).
- KCF4.7 (kconfigwidgets) `KConfigDialog` (`addPage` at `refs/kconfigwidgets/src/kconfigdialog.cpp:118` and `:141` with a `KCoreConfigSkeleton`; `showDialog` by name at `:267`; `updateSettings` at `:316`). `KConfigDialogManager` (`init` at `refs/kconfigwidgets/src/kconfigdialogmanager.cpp:100`, `setupWidget` at `:114`, `updateSettings` at `:356`, `hasChanged` at `:535`).

### 4b. File watching and notification
- KCF4.8 (kconfig) Notification entries: an entry gets `bNotify` when it is written with the `Notify` write flag (`Notify = 0x08 | Persistent`, `refs/kconfig/src/core/kconfigbase.h:55`), stored as `EntryNotify` (`refs/kconfig/src/core/kconfigdata_p.h:281`).
- KCF4.9 (kconfig) `KConfig::sync()` collects changed `(group, key)` pairs for entries that are dirty and have `bNotify`, into two maps: local (for the app file) and global (for `kdeglobals`). `refs/kconfig/src/core/kconfig.cpp:443-472` (global at `:467`, local at `:472`).
- KCF4.10 (kconfig) After writing, `sync()` sends the local changes with the object's sanitised D-Bus path (`/` + name) and the global ones to `/kdeglobals`, via `notifyClients`. Not sent for absolute-path configs. `refs/kconfig/src/core/kconfig.cpp:514-520`.
- KCF4.11 (kconfig) `KConfigPrivate::notifyClients` sends a session-bus signal named `ConfigChanged` on interface `org.kde.kconfig.notify` with a `QHash<QString, QByteArrayList>` argument (group path to key list). Compiled out unless `KCONFIG_USE_DBUS`. `refs/kconfig/src/core/kconfig.cpp:524-538`.
- KCF4.12 (kconfig) `KConfigWatcher::create(config)` returns a per-thread shared watcher for one `KSharedConfig`; the watcher is cached in a `QThreadStorage` keyed by the config pointer and removed on destruction. `refs/kconfig/src/core/kconfigwatcher.cpp:33-49`.
- KCF4.13 (kconfig) The watcher refuses absolute-path config names (warning). `refs/kconfig/src/core/kconfigwatcher.cpp:54-66`.
- KCF4.14 (kconfig) The watcher subscribes on the session bus to `ConfigChanged` at the object path for its own file, the paths in `additionalConfigSources()`, and `/kdeglobals` when `IncludeGlobals` is set. `refs/kconfig/src/core/kconfigwatcher.cpp:79-95`.
- KCF4.15 (kconfig) On a notification the watcher calls `reparseConfiguration()` on its config, then, for each changed group path (split on `\x1d`), emits `configChanged(const KConfigGroup &group, const QByteArrayList &names)`. `refs/kconfig/src/core/kconfigwatcher.cpp:106-120` (reparse at `:108`, emit at `:119`).
- KCF4.16 (kconfig) `KConfigWatcher` is a `QObject`; the signal is `configChanged`. `refs/kconfig/src/core/kconfigwatcher.h:44`, `:74`. Usage example in the header comment: `KConfigWatcher::Ptr watcher = KConfigWatcher::create(config);` `refs/kconfig/src/core/kconfigwatcher.h:26-31`.
- KCF4.17 (kconfig) `KConfig::reparseConfiguration` clears the entry map and the static global-file caches (`s_globalFilesAreInitialized = false`), then re-reads all files; unsaved dirty changes are synced first. `refs/kconfig/src/core/kconfig.cpp:697-718`.
- KCF4.18 (kconfig) Parsed global files are cached per thread in a `QCache` keyed by file list and locale, and invalidated by the files' last-modified times (UTC msecs). `refs/kconfig/src/core/kconfig.cpp:55-66` (cache type), `:799-835` (timestamp check and cache store).
- KCF4.19 (kconfig) Watching does not use inotify or QFileSystemWatcher in this code; file-level change is only signalled through the D-Bus notifications from a writer process (UNVERIFIED for any inotify use elsewhere in `src/`: rg for `inotify` not run).
