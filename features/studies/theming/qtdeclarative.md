## 1. Purpose and shape
- QD1.1 Qt Quick Controls 2 (QML module `QtQuick.Controls`) in Qt 6.13.0 alpha1 (`.cmake.conf:1` sets `QT_REPO_MODULE_VERSION "6.13.0"`, `.cmake.conf:2` sets prerelease `alpha1`). Language is C++ with QML. Each built-in look is a separate QML module with a C++ plugin. The style set is built into `qquickstyle.cpp:404-424` (`builtInStyles()`): Basic, Fusion, FluentWinUI3, Imagine, Material, Universal, plus iOS and macOS on Apple platforms and Windows on Windows (`#ifdef` blocks at lines 411-422). `NativeStyle` is a separate module (QD1.6).
- QD1.2 Layout of `src/quickcontrols/` (the directories that matter):
  - `qquickstyle.cpp/.h`, `qquickstyle_p.h`: style name resolution, config file reading, palette and font parsing, public `QQuickStyle` API. `src/quickcontrols/qquickstyle.cpp`
  - `qquickstyleplugin.cpp/_p.h`: base class `QQuickStylePlugin` every style plugin derives from; registers types, creates and updates the theme. `src/quickcontrols/qquickstyleplugin_p.h`
  - `qquickattachedpropertypropagator.cpp/.h`: base class for attached properties (Material, Universal, Imagine) that propagate to child items. `src/quickcontrols/qquickattachedpropertypropagator.h`
  - `basic/`, `fusion/`, `material/`, `universal/`, `imagine/`, `fluentwinui3/`, `ios/`, `macos/`, `windows/`: one directory per style. Each has `qtquickcontrols2<style>styleplugin.cpp`, a `qquick<style>theme` class and QML control files.
  - `quicknativestyle/`: the `QtQuick.NativeStyle` module (QStyle bridge), see QD1.6.
  - `doc/`: qdoc sources; `designer/`: Qt Designer plugin code; `qmldir`: the top-level module file.
- QD1.3 Build: `src/quickcontrols/CMakeLists.txt` declares the plugin target `qtquickcontrols2plugin` (`src/quickcontrols/CMakeLists.txt:44`), extends it with `qtquickcontrols2plugin.cpp` (`src/quickcontrols/CMakeLists.txt:74-76`), and adds the `IndirectBasic` resource (`src/quickcontrols/CMakeLists.txt:83-88`). Each style subdirectory has its own `CMakeLists.txt`. Top-level dependencies are declared in `dependencies.yaml` and `configure.cmake`; not read in detail.
- QD1.4 Version of this checkout: Qt 6.13.0-alpha1 (see QD1.1). The older standalone `qtquickcontrols2` repo was merged into this module (see `refs/qtquickcontrols2/README.md`, study `qtquickcontrols2.md`).

## 2. Theme input (how configuration reaches it)
- QD2.1 Style name, in priority order, resolved in `QQuickStylePrivate::resolve()` (`src/quickcontrols/qquickstyle.cpp:129-160`):
  1. A value already held in the `style` member, set by `QQuickStyle::setStyle()` (`qquickstyle.cpp:446-456`; the call must precede loading of QML that imports Controls, warning at line 452).
  2. `QGuiApplicationPrivate::styleOverride` (the `-style` command line value). `src/quickcontrols/qquickstyle.cpp:131-132`
  3. Environment variable `QT_QUICK_CONTROLS_STYLE`. `src/quickcontrols/qquickstyle.cpp:133-134`
  4. `Style` key in group `[Controls]` of the config file. `src/quickcontrols/qquickstyle.cpp:138-142`
  If still empty, `effectiveStyleName()` returns `"Basic"`. `src/quickcontrols/qquickstyle.cpp:258-261`
- QD2.2 Fallback style: `QT_QUICK_CONTROLS_FALLBACK_STYLE` env var (`qquickstyle.cpp:135-136`), then `FallbackStyle` key in `[Controls]` (`qquickstyle.cpp:143-144`), or `QQuickStyle::setFallbackStyle()`. The value must be a built-in name, otherwise it is cleared with a warning (`qquickstyle.cpp:149-154`). `QQuickStyle::setFallbackStyle` doc: `qquickstyle.cpp:461-468`.
- QD2.3 Config file location: env `QT_QUICK_CONTROLS_CONF` if the file exists (`qquickstyle.cpp:219`); otherwise the Qt resource `:/qtquickcontrols2.conf` (`qquickstyle.cpp:224`). The source of that resource was not located in the checkout (see section 8).
- QD2.4 Parsing: `QQuickStylePrivate::settings(group)` opens the file with `QSettings::IniFormat` and passes it through `QFileSelector` (so file selectors can pick a per-platform variant). Group is begun if non-empty. `src/quickcontrols/qquickstyle.cpp:300-313`
- QD2.5 Keys read from the config file, by function:
  - `[Controls]` `Style`, `FallbackStyle`: `qquickstyle.cpp:139-144`.
  - `[<StyleName>]` group (opened per style by `createTheme(name)`, `src/quickcontrols/qquickstyleplugin.cpp:169`), containing:
    - `Font` (a whole QFont value) or the sub-group `[Font]` with `Family`, `PointSize`, `PixelSize`, `StyleHint`, `Weight`, `Style`. `src/quickcontrols/qquickstyle.cpp:338-354`
    - `[Palette]` (opened at `src/quickcontrols/qquickstyle.cpp:377`) with sub-groups `[Normal]` and `[Disabled]`, each holding `QPalette::ColorRole` enum names as keys with color values. Names are resolved with `QMetaEnum::keyToValue`. `src/quickcontrols/qquickstyle.cpp:356-371` (`readColorGroup`), `qquickstyle.cpp:374-388` (`readPalette`, group names at lines 377, 380, 384).
  - Style-specific keys (for example Material `Variant`) are read in each style plugin, not in this shared code (the `createTheme` doc comment at `src/quickcontrols/qquickstyleplugin.cpp:156-157` says so). UNVERIFIED for the exact key list of each style: not read.
- QD2.6 Environment variables found in the studied code: `QT_QUICK_CONTROLS_STYLE`, `QT_QUICK_CONTROLS_FALLBACK_STYLE`, `QT_QUICK_CONTROLS_CONF`. Plus the `-style` command line through `QGuiApplicationPrivate::styleOverride`. `src/quickcontrols/qquickstyle.cpp:131-136, 219`
- QD2.7 System color scheme input: `QQuickStylePrivate::isDarkSystemTheme()` reads `QPlatformTheme::colorScheme()`; if the platform returns `Unknown`, it compares window text lightness with window lightness. `src/quickcontrols/qquickstyle.cpp:391-402`. The platform theme comes from `QGuiApplicationPrivate::platformTheme()`, so the value is whatever the Qt platform plugin (for example the QPA theme plugin) provides.

## 3. Color and style model
- QD3.1 The palette is a plain `QPalette` (Qt Core/Gui type). Each theme keeps one palette per `QQuickTheme::Scope`. Scopes: System, Button, CheckBox, ComboBox, GroupBox, ItemView, Label, ListView, Menu, MenuBar, RadioButton, SpinBox, Switch, TabBar, TextArea, TextField, ToolBar, ToolTip, Tumbler. `src/quicktemplates/qquicktheme_p.h:36-53` (enum), `setPalette/palette` at lines 60-62 (declarations).
- QD3.2 Lookup: `QQuickTheme::palette(scope)` (`src/quicktemplates/qquicktheme.cpp:112`). If the theme has `usePlatformPalette()` set, it asks the platform theme for a palette (`platformTheme->palette(platformPalette(scope))`, lines 116-119). If the config file provided a palette, that palette is resolved on top of the platform palette, and the System scope clears the resolve mask (lines 123-131). Otherwise the theme's own stored palette is used (line 134-135).
- QD3.3 Default palette of every control: `QQuickControlPrivate::defaultPalette()` returns `QQuickTheme::palette(QQuickTheme::System)`. `src/quicktemplates/qquickcontrol.cpp:478-480`. Per-control palette scopes are chosen by the control's own code (not studied).
- QD3.4 Font counterpart: `QQuickTheme` also maps scopes to `QPlatformTheme::Font` values (`platformFont(scope)`, `src/quicktemplates/qquicktheme.cpp:27-40`).
- QD3.5 Theme object: `QQuickTheme` (`src/quicktemplates/qquicktheme_p.h`) is created once per process by `QQuickStylePlugin::createTheme()` (`src/quickcontrols/qquickstyleplugin.cpp:162`), which reads the config group, sets the System-scope font and palette from the config (`qquickstyleplugin.cpp:169-180`) and stores the instance in `QQuickThemePrivate::instance`. Style-specific themes (`QQuickMaterialTheme`, `QQuickUniversalTheme`, ...) then fill in the other scopes through `initializeTheme(theme)`.
- QD3.6 Dark and light: Material exposes `enum Theme { Light, Dark, System }` (`src/quickcontrols/material/qquickmaterialstyle_p.h:107-111`). `System` is resolved once in the constructor with `effectiveTheme()`, which calls `QQuickStylePrivate::isDarkSystemTheme()` (`src/quickcontrols/material/qquickmaterialstyle.cpp:434-438`, constructor at 441-456, theme member initialised at line 449). Default theme value is `Light` (`qquickmaterialstyle_p.h:355`); the static default `globalTheme` is `Light` at `qquickmaterialstyle.cpp:348`. Universal exposes `enum Theme { Light, Dark, System }` at `src/quickcontrols/universal/qquickuniversalstyle_p.h:71`.
- QD3.7 Attached-property style selection: Material and Universal (and Imagine) are QML attached types. `QML_ATTACHED(QQuickMaterialStyle)` plus `QML_UNCREATABLE("")` at `src/quickcontrols/material/qquickmaterialstyle_p.h:102-103`. The C++ factory is `QQuickMaterialStyle::qmlAttachedProperties` (`src/quickcontrols/material/qquickmaterialstyle.cpp:458-460`). The Material properties `theme`, `primary`, `accent`, `foreground`, `background`, `elevation`, `roundedScale`, `containerStyle` are declared as Q_PROPERTY at `qquickmaterialstyle_p.h:29-37`. Universal declares `theme` and `accent` at `src/quickcontrols/universal/qquickuniversalstyle_p.h:31-32`. Universal and Imagine use `QML_ATTACHED` at `universal/qquickuniversalstyle_p.h:62` and `imagine/qquickimaginestyle_p.h:32`.
- QD3.8 Propagation: attached-property objects derive from `QQuickAttachedPropertyPropagator` (`qquickmaterialstyle_p.h:26`). Setting a property on one object iterates its child attached objects and updates them (example: `setPrimary` loop, `src/quickcontrols/material/qquickmaterialstyle.cpp:590`). The base class is in `src/quickcontrols/qquickattachedpropertypropagator.cpp` (544 lines; not read in full).
- QD3.9 Derived colors: Material stores hard-coded ARGB constants for light and dark variants (for example `static const QRgb switchDisabledUncheckedTrackBorderColorLight = 0x1E1C1B1F;` at `qquickmaterialstyle.cpp:425`, with a `...Dark` counterpart on the next line). Its use is a ternary on the effective theme (for example `qquickmaterialstyle.cpp:1090`). UNVERIFIED: the selection for every other property was not read.
- QD3.10 Per-state handling: Controls QML files select state colors (pressed, hovered, disabled, focus) in their own QML and `*Color` properties (for example Material `primaryTextColor`, `highlightedRippleColor` in `qquickmaterialstyle_p.h:43-47`). The generic state handling in the QML templates was not studied.
- QD3.11 Refresh on palette or theme change: `QQuickStylePlugin` installs a `QQuickThemeChangeObserver` that listens for `QEvent::ApplicationPaletteChange` and `QEvent::ThemeChange` on the style hints object and emits `paletteOrThemeChanged` (`src/quickcontrols/qquickstyleplugin.cpp:40-41`, connection at `qquickstyleplugin.cpp:126-127` calls `updateTheme()`). Material and Universal `updateTheme()` recompute their colors through the theme (`qtquickcontrols2materialstyleplugin.cpp:47-49` calls `theme.updateTheme()`).

## 4. Output and rendering path
- QD4.1 Call chain from selection to a style plugin (ordered):
  1. QML `import QtQuick.Controls` loads the main `QtQuick.Controls` module. `QQuickStyle::setStyle` or the environment set the name; `QQuickStylePrivate::resolve()` runs lazily (`src/quickcontrols/qquickstyle.cpp:127-160`).
  2. Each style plugin's `registerTypes(uri)` runs (`src/quickcontrols/qquickstyleplugin.cpp:62`). If no `QtQuick.Controls` is imported and no style name was set, it selects its own name at compile time (`qquickstyleplugin.cpp:70-74`).
  3. `createTheme()` runs if no theme exists yet, for every style plugin (`qquickstyleplugin.cpp:82-88`; `createTheme` defined at line 162). Then the plugin checks whether it belongs to the current or fallback style (`qquickstyleplugin.cpp:93-99`; early return at line 99 otherwise). If it does, `initializeTheme(theme)` runs (`qquickstyleplugin.cpp:121`).
  4. Material example: `QtQuickControls2MaterialStylePlugin::initializeTheme` calls `QQuickMaterialStyle::initGlobals()` and `theme.initialize(theme)` (`src/quickcontrols/material/qtquickcontrols2materialstyleplugin.cpp:41-45`).
  5. A `QQuickThemeChangeObserver` is created and connected to `updateTheme()` (`qquickstyleplugin.cpp:124-127`).
- QD4.2 Plugin entry point: each style class derives from `QQuickStylePlugin` (which derives from `QQmlExtensionPlugin`), uses `Q_PLUGIN_METADATA(IID QQmlExtensionInterface_iid)`, returns its name from `name()`, and implements `initializeTheme()` and `updateTheme()`. Example: `src/quickcontrols/material/qtquickcontrols2materialstyleplugin.cpp:15-24` (class and metadata), `:36-39` (name "Material"), `:41-45`, `:47-49`. Same pattern: `universal/qtquickcontrols2universalstyleplugin.cpp:18, 36, 41, 47`. Other style names: `basic/qtquickcontrols2basicstyleplugin.cpp:37`, `fusion/qtquickcontrols2fusionstyleplugin.cpp:38`, `imagine/qtquickcontrols2imaginestyleplugin.cpp:39`, `fluentwinui3/qtquickcontrols2fluentwinui3styleplugin.cpp:40`, `macos/qtquickcontrols2macosstyleplugin.cpp:36`, `windows/qtquickcontrols2windowsstyleplugin.cpp:34`, `ios/qtquickcontrols2iosstyleplugin.cpp:40`.
- QD4.3 Registration: the plugin constructor takes the address of the generated `qml_register_types_QtQuick_Controls_Material` function (`material/qtquickcontrols2materialstyleplugin.cpp:30-33`, `volatile auto registration` at line 32), which keeps the registration object linked. `QQuickStylePlugin::registerTypes(uri)` (`qquickstyleplugin.cpp:62`) is the Qt entry for the call.
- QD4.4 Per-style QML: each style directory contains QML control files with the same names (Button.qml, CheckBox.qml, ...). The controls draw with Qt Quick items (Rectangle, Shape, shaders in `material/shaders/`). Shader and image assets: `material/images/`, `universal/images/`, `basic/images/`, `material/shaders/`. The exact asset-to-control mapping was not studied.
- QD4.5 The `NativeStyle` path (`src/quickcontrols/quicknativestyle/`): plugin `QtQuickControls2NativeStylePlugin` with name `"NativeStyle"` (`quicknativestyle/qtquickcontrols2nativestyleplugin.cpp:23-35`), module URI `QtQuick.NativeStyle` (`quicknativestyle/CMakeLists.txt:45-46`). It uses a singleton `QStyle` (`quicknativestyle/qstyle/qqc2qnativestyle.cpp:42-52`, `StyleSingleton`; accessor `style()` at lines 111-113). Selection: `QMacStyle` on macOS (`qqc2qnativestyle.cpp:79`), `QWindowsXPStyle` on Windows, with `refreshPalette()` when `QStyleHints::colorScheme()` is Dark (lines 81-83), else `QCommonStyle` (line 88). The style is refreshed on `QStyleHints::colorSchemeChanged` by calling `handleThemeChange()` (`qqc2qnativestyle.cpp:96-98`). The drawing code lives in `quicknativestyle/qstyle/qqc2qcommonstyle.cpp` (6137 lines, not read in full) and `qqc2qstyle.cpp` (389 lines, not read in full).
- QD4.6 Material theme initialisation calls `QQuickMaterialStyle::initGlobals()` (`material/qtquickcontrols2materialstyleplugin.cpp:42`), which sets static defaults used by every instance. `globalTheme`, `globalVariant` and the other `global*` values are declared near `qquickmaterialstyle.cpp:366`.

## 5. Extension and integration points
- QD5.1 A custom style is any QML module that is not in `builtInStyles()`. `QQuickStylePrivate::resolve()` sets `custom = true` for it (`qquickstyle.cpp:190`). Custom style names are allowed in `QQuickStyle::setStyle`; only the fallback name is restricted to the built-in list (`qquickstyle.cpp:149-154`).
- QD5.2 Style-specific config group: the group name equals the style name passed to `createTheme(name)` (`qquickstyleplugin.cpp:169`). Config key names for fonts and palettes are fixed by the shared reader (section 2).
- QD5.3 File selectors: `QFileSelector` is used when reading the config file (`qquickstyle.cpp:306`), and the non-fallback style name is added as a static selector (`QFileSelectorPrivate::addStatics`, `qquickstyleplugin.cpp:111`; removed in `unregisterTypes`, `qquickstyleplugin.cpp:141`).
- QD5.4 ABI and version coupling: the style plugins are Qt plugins built against private headers (`_p.h` files are used directly, for example `qquickmaterialstyle_p.h`, `qquickstyleplugin_p.h`). The module targets Qt 6 (`QTypeRevision` and `QML_*` macros). Exports: `Q_QUICKCONTROLS2_EXPORT` on `QQuickStyle` (`src/quickcontrols/qquickstyle.h:14`) and `QQuickStylePrivate` (`qquickstyle_p.h:27`), and `Q_QUICKCONTROLS2MATERIAL_EXPORT` on `QQuickMaterialStyle` (`material/qquickmaterialstyle_p.h:26`). UNVERIFIED: the exact soname and install path of each style plugin (CMake install rules not read).
- QD5.5 Discovery: the import `QtQuick.Controls.Material` (and the others) is a separate QML module with a `qmldir`. The top-level `QtQuick.Controls` module chooses which one is used by runtime or compile-time selection (section 4 step 2). `src/quickcontrols/qmldir` and `src/quickcontrols/CMakeLists.txt`.
- QD5.6 Designer: `src/quickcontrols/designer/` holds Qt Designer plugin code (not studied).

## 7. Facts of note
- QD7.1 The `QQuickStylePrivate::resolve()` precedence is defined by code order at `qquickstyle.cpp:131-146`. Note that `QQuickStyle::setStyle` at `qquickstyle.cpp:446-456` must run before QML imports `QtQuick.Controls` (warning at line 452 and a check at 450-451).
- QD7.2 `QQuickStyle::setStyle` and the other runtime calls are ignored once the style is resolved (`resolved` flag, `qquickstyle.cpp:192` sets `resolved = true`).
- QD7.3 The style plugin for a style that is neither current nor fallback still creates the theme object so that config fonts and palettes apply (comment at `qquickstyleplugin.cpp:77-80`). The theme is created before the belonging check result is used; the early return is at line 99 (`qquickstyleplugin.cpp:93-99`).
- QD7.4 Material and Universal define `System` as a theme value that is resolved at construction time (`qquickmaterialstyle.cpp:434-438`, `m_systemTheme` at line 448). `setTheme` compares against the effective theme and a `systemThemeChanged` flag (`qquickmaterialstyle.cpp:478`); the rest of that path was not read.
- QD7.5 Known-broken and deprecation markers: `material/qquickmaterialstyle_p.h:40-41` marks `primaryColor` and `accentColor` with `// TODO: remove?`.
- QD7.6 The `QQuickStylePlugin` comment at `qquickstyleplugin.cpp:89-90` refers to QTBUG-117403 and says fallback style themes must be initialised without also initialising the Basic style. Verified text only.
- QD7.7 Wayland, X11 and Windows native style behaviour is not covered by the Quick Controls styles listed here; it is reached only through `NativeStyle` (QD4.5).
