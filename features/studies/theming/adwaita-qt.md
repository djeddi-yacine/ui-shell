## 1. Purpose and shape
- AQ1.1 A native Qt style "to bend Qt5/Qt6 applications to look like they belong into GNOME Shell", providing four Adwaita variants (`README.md:5-7`, `README.md:3` "Adwaita-qt project is unmaintained a no longer actively developed."). Languages: C++ (Qt widgets), SCSS compiled to CSS, Qt resource files.
- AQ1.2 Top-level layout: `src/style/` (style plugin, `Style` class, X11 helper, `adwaita.json`, `adwaita.themerc`); `src/lib/` (`libadwaitaqt` shared library: colours, renderer, animations, window manager, stylesheet build); `src/demo/` (widget factory demo, `widgetfactory.ui`); `data/` (4 files, screenshots); `cmake/`; `AUTHORS`; `README.md`.
- AQ1.3 Build system: CMake. Qt minimum 6.2.0 when `USE_QT6` is ON, otherwise 5.15.2 (`CMakeLists.txt:8`, `:11`, `:16`). C++17 is set for Qt 6 (`CMakeLists.txt:12`). The library target is `adwaitaqt${ADWAITAQT_SUFFIX}` (`src/lib/CMakeLists.txt:92`, `add_library(... SHARED ...)`). The SCSS compiler `sassc` is found with `find_program(SASSC_EXECUTABLE sassc)` (`src/lib/CMakeLists.txt:68`); if absent, the build uses the committed processed CSS (`src/lib/CMakeLists.txt:80-81`, `STYLESHEET_PATH` set to `stylesheet/processed`).

## 2. Theme input (how configuration reaches it)
- AQ2.1 Variant selection by style key: `StylePlugin::create(key)` maps the key (lower-cased) to a variant enum (`src/style/adwaitastyleplugin.cpp:30-49`): "adwaita" to `Adwaita::Adwaita` (line 33), "adwaita-dark" to `AdwaitaDark` (line 37), "adwaita-highcontrast" or "highcontrast" to `AdwaitaHighcontrast` (lines 40-42), "adwaita-highcontrastinverse" or "highcontrastinverse" to `AdwaitaHighcontrastInverse` (lines 44-47). The plugin key list is `keys()` at `adwaitastyleplugin.cpp:57-58`, with "Adwaita-Light" also listed.
- AQ2.2 Plugin metadata: `Q_PLUGIN_METADATA(IID "org.qt-project.Qt.QStyleFactoryInterface" FILE "adwaita.json")` (`src/style/adwaitastyleplugin.h:32`). The file `src/style/adwaita.json` contains `{ "Keys": [ "Adwaita", "Adwaita-Dark", "Adwaita-HighContrast", "Adwaita-HighContrastInverse", "HighContrast", "HighContrastInverse" ] }`.
- AQ2.3 Automatic variant: when the variant is `Unknown`, `StyleOptions::colorVariant()` returns `AdwaitaDark` or `Adwaita` depending on `ColorsPrivate::isDarkMode()` (`src/lib/adwaita.cpp:166-167`). `ColorsPrivate::isDarkMode()` is at `src/lib/adwaitacolors.cpp:418`. It takes `QGuiApplication::palette().color(QPalette::Text)`, computes `sqrt(0.299 R^2 + 0.587 G^2 + 0.114 B^2)` and returns true when the result is greater than 128 (`adwaitacolors.cpp:420-424`, comparison at line 423, `return true` at line 424). So a light text colour selects the dark variant.
- AQ2.4 Theme file: `src/style/adwaita.themerc` starts with `[Misc]`, `Name=Adwaita`, `Comment=Qt widget style for GNOME` (lines 1-3). Installed to the QT plugin directory only through the style target (`src/style/CMakeLists.txt:44`, `install(TARGETS ... DESTINATION "${QT_PLUGINS_DIR}/styles")`). Consumption of the themerc by the code was not traced (UNVERIFIED).
- AQ2.5 Window-manager options: `Adwaita::Config` values are compile-time constants, for example `TitleWidgetDrawFrame {true}` (`src/lib/adwaita.h:87`). No runtime config file for these was found.
- AQ2.6 Environment variables and command-line flags: None found in the files studied.

## 3. Color and style model
- AQ3.1 Colour source: SCSS partials `src/lib/stylesheet/_colors.scss` (74 lines) and `_colors-hc.scss` define the palette as Sass variables such as `$bg_color`, `$fg_color`, `$base_color`, `$text_color`, `$selected_bg_color` (`_colors.scss:4-10`). Each variant file (`Adwaita-light.scss`, `Adwaita-dark.scss`, `Adwaita-hc.scss`, `Adwaita-hc-dark.scss`) imports `colors` and `drawing` (`Adwaita-light.scss:3-4`).
- AQ3.2 Compiled colour data: `src/lib/stylesheet/processed/Adwaita-light.css` (95 lines) holds the Sass output as `@define-color` lines, for example `@define-color bg_color #f6f5f4;` (line 3) and `@define-color selected_bg_color #3584e4;` (line 6), and `@define-color headerbar_bg_color white;` (line 15). Four processed files exist: `Adwaita-light.css`, `Adwaita-dark.css`, `Adwaita-hc.css`, `Adwaita-hc-dark.css`.
- AQ3.3 Loading the colour table: `ColorsPrivate::ColorsPrivate()` iterates over `light`, `dark`, `hc`, `hc-dark` (`src/lib/adwaitacolors.cpp:259-261`), maps each to a `ColorVariant` (lines 262-270), and opens the Qt resource `:/stylesheet/Adwaita-%1.css` (`adwaitacolors.cpp:273-274`). It then reads lines, and for lines starting with `@define-color` (`adwaitacolors.cpp:288`) parses the colour name and value into a per-variant table (parse details not read in full).
- AQ3.4 Named colour lookup: `ColorsPrivate::adwaitaColor(AdwaitaColor color, ColorVariant variant)` (`src/lib/adwaitacolors.cpp:369`) returns a `QColor`; `adwaitaWidgetColor(const QString &color, ColorVariant variant)` (`adwaitacolors.cpp:374`) looks up by name.
- AQ3.5 Palette construction: `Colors::palette(ColorVariant variant)` (`src/lib/adwaitacolors.cpp:442`) builds a `QPalette` by setting roles per colour group. Examples: `QPalette::All/Window` from `bg_color` (`adwaitacolors.cpp:453`), `All/WindowText` from `fg_color` (`:454`), `Disabled/Window` from `insensitive_bg_color` (`:477`), `Inactive/Window` from `backdrop_bg_color` (`:499`). The role list used for the palette is at `adwaitacolors.cpp:434`.
- AQ3.6 Shade formulas: the Sass functions `lighten()`, `darken()`, `desaturate()` produce the shaded values. For example `$base_color` = `lighten(desaturate(#241f31, 100%), 2%)` in the dark variant and `$bg_color` = `darken(desaturate(#3d3846, 100%), 4%)` (`_colors.scss:4`, `:6`), and `$selected_bg_color` = `darken(#3584e4, 20%)` in the dark variant (`_colors.scss:10`). The C++ side does not compute shades; it reads the compiled values. Hover and pressed shades are defined in `_colors.scss` and `_drawing.scss` (not read in full).
- AQ3.7 Per-state handling: `StyleOptions` carries the widget state, and colour helpers in `src/lib/adwaitacolors.cpp` select disabled / inactive / active colours from `options.palette().currentColorGroup()`. Examples: `bool isDisabled = ... == QPalette::Disabled;` and `isInactive` for `QPalette::Inactive` (`adwaitacolors.cpp:204-205`, and `:235` for a further disabled check). Window-active colours use `options.active() ? QPalette::Active : QPalette::Inactive` (`adwaitacolors.cpp:555`, `:560`).
- AQ3.8 Animations: `src/lib/animations/` holds engines and data for widget state, busy indicator, scrollbar, spinbox, tab bar, header view, toolbox, dial (`adwaitawidgetstateengine.cpp`, `adwaitatabbarengine.cpp`, and others). These produce the opacity used by the renderer (engine internals not read).

## 7. Facts of note
- AQ7.1 The project is marked unmaintained: "Adwaita-qt project is unmaintained a no longer actively developed." (`README.md:3`).
- AQ7.2 Variant is decided by the style key (AQ2.1); when no variant is set, the luma of the application's text colour decides dark or light (AQ2.3).
- AQ7.3 Colours are not computed in C++. They are read from CSS `@define-color` lines that Sass produced (AQ3.2-AQ3.4), so the C++ side depends on the processed or compiled CSS, and the SCSS builds only when sassc is installed (AQ1.3).
- AQ7.4 The processed CSS files are committed (`src/lib/stylesheet/processed/`). The build uses them when sassc is not found (AQ1.3).
- AQ7.5 The GTK theme-variant hint is written as an X11 property (AQ4.6). The code path is X11-specific; Wayland is not addressed in the file list (UNVERIFIED for Wayland behaviour).
- AQ7.6 License: GPL-2.0 and LGPL-2.0 texts are both in the repo (`COPYING`, `LICENSE.GPL2`, `LICENSE.LGPL2`). The licence that applies to each file was not checked (UNVERIFIED).
