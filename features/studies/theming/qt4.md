# qt4: Qt 4.8 source tree, style and palette selection plus the built-in GTK+ style

Source: refs/qt4 (shallow clone; commit 0a2f2382, 2015-10-23; branch 4.8). License: LICENSE.LGPL (LGPL v2.1 text; file LICENSE.LGPLv21 and LICENSE.LGPLv3 also present), plus LGPL_EXCEPTION.txt, cited. Scope: src/gui/styles/ (qstyle, qcommonstyle, qwindowsstyle, qplastiquestyle, qcleanlooksstyle, qgtkstyle, qgtkstyle_p, qgtkpainter, qstylehelper, qstylefactory, qstyleplugin, qstylesheetstyle head only), src/gui/kernel/ (qapplication.cpp style/palette selection, qapplication_x11.cpp settings, qguiplatformplugin.cpp), src/gui/painting/qcolor.cpp (lighter/darker), src/gui/kernel/qpalette.h, tools/qtconfig/mainwindow.cpp (save path), configure (GTK switch). Not studied: qmacstyle, qwindowsvista/xp internals, QStyleSheetStyle rendering internals, qs60/qcde/qmotif drawing code.
Id prefix: Q4.

## 1. Purpose and shape
- Q4.1.1 Qt 4.8 is a C++ GUI toolkit (LGPL). Its style layer is a QStyle class hierarchy that draws every standard widget element; the GTK+ integration is one of those QStyle subclasses (QGtkStyle), loaded with `dlopen` at run time. `src/gui/styles/qstyle.h:68`, `src/gui/styles/qgtkstyle.h:61`.
- Q4.1.2 Built-in style hierarchy (each class is a subclass of the one shown): QStyle > QCommonStyle (`src/gui/styles/qcommonstyle.h:54`); QCommonStyle > QWindowsStyle (`src/gui/styles/qwindowsstyle.h:57`), QCommonStyle > QMotifStyle (`src/gui/styles/qmotifstyle.h:60`), QCommonStyle > QProxyStyle (`src/gui/styles/qproxystyle.h:56`); QWindowsStyle > QPlastiqueStyle (`src/gui/styles/qplastiquestyle.h:56`), QWindowsStyle > QCleanlooksStyle (`src/gui/styles/qcleanlooksstyle.h:56`); QCleanlooksStyle > QGtkStyle (`src/gui/styles/qgtkstyle.h:61`); QMotifStyle > QCDEStyle (`src/gui/styles/qcdestyle.h:56`); QWindowsStyle > QWindowsXPStyle (`src/gui/styles/qwindowsxpstyle.h:56`); QWindowsXPStyle > QWindowsVistaStyle (`src/gui/styles/qwindowsvistastyle.h:56`).
- Q4.1.3 Language C++ with Qt's moc/private-header conventions. Build system is qmake (`.pro`/`.pri`) driven by the top-level `configure` script.
- Q4.1.4 Layout that matters:
  - `src/gui/styles/`: all style classes, factory, plugin interface, GTK integration (`qgtkstyle.cpp`, `qgtkstyle_p.cpp`, `qgtkstyle_p.h`, `qgtkpainter.cpp`), `styles.pri` (build selection).
  - `src/gui/kernel/`: `qapplication.cpp` (default style choice), `qapplication_x11.cpp` (reads the Qt settings file), `qguiplatformplugin.cpp` (platform plugin that names the default style), `qpalette.h` (color roles).
  - `src/gui/painting/qcolor.cpp`: `QColor::lighter()` / `darker()` shade math.
  - `src/gui/image/`, `src/gui/dialogs/`: not studied except where cited.
  - `tools/qtconfig/`: the Qt configuration GUI that writes the settings file.
  - `configure`: build switches (`-gtkstyle`, `-no-gtkstyle`) and pkg-config flags.
  - `src/corelib/kernel/qcoreapplication.cpp`: `QT_PLUGIN_PATH` handling.
  - `LICENSE.*`, `header.*`: license texts.
- Q4.1.5 Build gating for the GTK style: `styles.pri` adds the GTK sources only when `styles` contains `gtk` and sets `QT_CFLAGS_QGTKSTYLE` / `QT_LIBS_QGTKSTYLE` (`src/gui/styles/styles.pri:41-43`, `:112-118`). Otherwise `DEFINES += QT_NO_STYLE_GTK` (`src/gui/styles/styles.pri:124`). The flags come from `pkg-config gtk+-2.0 >= 2.10 atk` in `configure:6412`. The switch is `-gtkstyle` / `-no-gtkstyle` (`configure:4289-4290`, option list at `configure:2128`).

## 2. Theme input (how configuration reaches it)
- Q4.2.1 Environment variable `QT_STYLE_OVERRIDE`: read only when Qt is built with `QT_BUILD_INTERNAL` (`src/gui/kernel/qapplication.cpp:1451-1452`); otherwise `envStyle` is empty. Precedence is `styleOverride` (set by the settings file or the `-style` argument), then `envStyle`, then the desktop default (`src/gui/kernel/qapplication.cpp:1455-1462`).
- Q4.2.2 Environment variable `QT_PLATFORM_PLUGIN`: names a GUI platform plugin (`/gui_platform` plugin directory). If unset on X11, the key is `kde` when the X11 desktop environment is KDE, else the value of `DESKTOP_SESSION` (`src/gui/kernel/qguiplatformplugin.cpp:86-95`). The plugin is loaded only when `QApplication::desktopSettingsAware()` is true (`src/gui/kernel/qguiplatformplugin.cpp:100-104`). If no plugin loads, a built-in default `QGuiPlatformPlugin` is used (`src/gui/kernel/qguiplatformplugin.cpp:106-109`).
- Q4.2.3 Environment variable `QT_PLUGIN_PATH`: colon-separated list of extra plugin directories, canonicalised and added to the library paths (`src/corelib/kernel/qcoreapplication.cpp:2540-2550`).
- Q4.2.4 Environment variable `GTK2_RC_FILES`: colon-separated list of gtkrc files. The GTK style parses them line by line for `gtk-theme-name` (`src/gui/styles/qgtkstyle_p.cpp:657-672`).
- Q4.2.5 GConf fallback for the GTK theme name: if no gtkrc gives a name, `/desktop/gnome/interface/gtk_theme` is read through `resolveGConf()` (`src/gui/styles/qgtkstyle_p.cpp:682-684`, function `getThemeName` at `:651`). Other GConf keys read: `/desktop/gnome/interface/buttons_have_icons` (`src/gui/styles/qgtkstyle.cpp:659`) and `/desktop/gnome/interface/menus_have_icons` (`src/gui/kernel/qapplication_x11.cpp:2406`).
- Q4.2.6 Qt settings file: `QSettings(QSettings::UserScope, "Trolltech")`, group `Qt` (`src/gui/kernel/qapplication_x11.cpp:866-867`). Keys read by `QApplicationPrivate::x11_apply_settings()`:
  - `Palette/active`, `Palette/inactive`, `Palette/disabled`: string lists of color names, indexed by `QPalette::ColorRole` (`src/gui/kernel/qapplication_x11.cpp:894-911`).
  - `font` (`src/gui/kernel/qapplication_x11.cpp:931-938`, the KDE `kdeglobals` font is tried first on KDE).
  - `style` (`src/gui/kernel/qapplication_x11.cpp:959`). Used as `styleOverride` at startup, or applied via `QApplication::setStyle` later (`:961-975`). If empty and xrender is on, the platform plugin's `styleName()` is used (`:961-964`).
  - `libraryPath` with a version prefix `<major>.<minor>/libraryPath`, used only when not using the X server (`src/gui/kernel/qapplication_x11.cpp:2618-2624`) and appended to library paths earlier in the same function (`:939-957`, not fully read).
  - Other keys listed in the comment block (`doubleClickInterval`, `cursorFlashTime`, `wheelScrollLines`, `colorSpec`, `defaultCodec`, `globalStrut/*`, `GUIEffects`, `Font Substitutions/*`) at `src/gui/kernel/qapplication_x11.cpp:872-889`.
- Q4.2.7 Writer of the settings file: the `tools/qtconfig` GUI. It writes `font`, `Palette/active|inactive|disabled`, `fontPath`, `embedFonts`, `style`, timing keys (`tools/qtconfig/mainwindow.cpp:518-547` and onward). When the chosen style equals the desktop theme name, `style` is written empty and palettes are not written (`tools/qtconfig/mainwindow.cpp:530-534`, `:547`).
- Q4.2.8 Command line: `-style <name>` is a Qt command line option (not read in this study; `UNVERIFIED: exact parsing location not traced`).
- Q4.2.9 The GTK style itself reads no Qt-side config file: its inputs are the live GTK 2 runtime (via `gtk_init` and `gtk_settings_get_default`) and the GTK settings it reads through `g_object_get` (`src/gui/styles/qgtkstyle.cpp:467-469`, `:590-591`, `:642-643`, `:666-667`).

## 3. Color and style model
- Q4.3.1 Palette roles: `QPalette::ColorRole` enum with `WindowText, Button, Light, Midlight, Dark, Mid, Text, BrightText, ButtonText, Base, Window, Shadow, Highlight, HighlightedText, Link, LinkVisited, AlternateBase, NoRole, ToolTipBase, ToolTipText, NColorRoles` (`src/gui/kernel/qpalette.h:93-101`). Color groups: `Active`, `Inactive`, `Disabled` (`src/gui/kernel/qpalette.h`, enum `ColorGroup`, not re-read).
- Q4.3.2 The GTK style builds a palette in `QGtkStyle::standardPalette()` (`src/gui/styles/qgtkstyle.cpp:219`). The base is `QCleanlooksStyle::standardPalette()` (`:223`). Then colors are read from live GTK style objects: the default `GtkStyle` from `d->gtkStyle()` (`:225`) gives the window background, the `GtkButton` widget gives the foreground, the `GtkEntry` widget gives base and text (normal, selected and active states) (`:226-243`), and each 16-bit GdkColor channel is converted with `>>8` (`:244-251`).
- Q4.3.3 Derived palette colors in the GTK path use the Qt QColor shade functions: `bg.lighter(125)` for Light, `bg.darker(130)` for Shadow, `bg.darker(120)` for Dark (`src/gui/styles/qgtkstyle.cpp:256-258`). The alternate row color is `base.lighter(93)` with a comment that it mirrors GTK's `draw_flat_box` (`:264`). GTK `odd-row-color` overrides it when set (`:266-269`).
- Q4.3.4 Shade formula, `QColor::lighter(factor)` / `darker(factor)`: both are inline wrappers over `light()` / `dark()` (`src/gui/painting/qcolor.h:298-304`). `light(f)`: if f < 100 it calls `darker(10000/f)`; otherwise it converts to HSV, sets `value = (f*value)/100` (clamped to 65535 with saturation reduced on overflow), and converts back (`src/gui/painting/qcolor.cpp:2295-2313`). `dark(f)`: if f < 100 it calls `lighter(10000/f)`; otherwise `value = (value*100)/f` in HSV (`src/gui/painting/qcolor.cpp:2345-2357`). So `darker(200)` halves the HSV value and `lighter(150)` multiplies it by 1.5.
- Q4.3.5 Shade use in the built-in Cleanlooks style (the base of GTK style): many `lighter(NNN)` / `darker(NNN)` calls on palette colors, e.g. `option->palette.button().color().darker(110)` (`src/gui/styles/qcleanlooksstyle.cpp:685`), `dark.lighter(135)` (`:697`), `option->palette.highlight().color().darker(180)` (`:558`).
- Q4.3.6 Other roles: QPalette has `Foreground` = `WindowText` and `Background` = `Window` as aliases (`src/gui/kernel/qpalette.h:101`), marked `### Qt 5: remove`.
- Q4.3.7 Per-state handling: style options carry `State_*` flags (not traced in this study). The GTK style maps Qt states to `GtkStateType` values at paint time (`QGtkPainter::paintBox` takes a `GtkStateType state` argument, `src/gui/styles/qgtkpainter.cpp:291-293`). Light/dark color-scheme handling: `UNVERIFIED: Qt 4.8 has no color-scheme concept; the palette is taken from GTK widget colors only.`
- Q4.3.8 Metrics and fonts: `QGtkStyle::pixelMetric()` reads `gtk-icon-sizes` and the `gtk-button` value from the GTK settings (`src/gui/styles/qgtkstyle.cpp:467-474`). Theme font: `QGtkStylePrivate::getThemeFont()` (declared at `src/gui/styles/qgtkstyle_p.h:335`, defined at `src/gui/styles/qgtkstyle_p.cpp:866`, used at `src/gui/styles/qgtkstyle.cpp:334`).
- Q4.3.9 Style-level state: `QApplicationPrivate::app_style`, `styleOverride`, `desktopStyleKey()` (`src/gui/kernel/qapplication_p.h:308`).

## 4. Output and rendering path
- Q4.4.1 Startup, in order:
  1. `QApplication::style()` (`src/gui/kernel/qapplication.cpp:1438`) creates the app style on first use if none exists.
  2. Chooses the key: `styleOverride`, then `QT_STYLE_OVERRIDE` (internal builds only), then `desktopStyleKey()` (`src/gui/kernel/qapplication.cpp:1455-1462`).
  3. `QStyleFactory::create(key)` (`src/gui/kernel/qapplication.cpp:1465`). If that returns null, the first style from `QStyleFactory::keys()` is used (`:1466-1472`).
  4. `QApplication::style()` takes ownership with `setParent(qApp)` (`src/gui/kernel/qapplication.cpp:1478-1479`).
- Q4.4.2 `desktopStyleKey()` returns `qt_guiPlatformPlugin()->styleName()` (`src/gui/kernel/qapplication.cpp:2102-2104`). The default `QGuiPlatformPlugin::styleName()` returns "WindowsXP"/"Windows" on Windows, "Macintosh" on Mac, "Plastique" on QWS/QPA, and on X11 uses KDE's `QKde::kdeStyle()` for KDE, "GTK+" for GNOME when the GTK style is registered, else "cleanlooks" when xrender is on (`src/gui/kernel/qguiplatformplugin.cpp:131-177`, X11 branch `:161-177`).
- Q4.4.3 `QStyleFactory::create(key)` (`src/gui/styles/qstylefactory.cpp:121`): lowercases the key and matches built-in names in order: windows, windowsce, windowsmobile, windowsxp, windowsvista, motif, cde, s60, plastique, cleanlooks, `gtk` or `gtk+` (QGtkStyle), macintosh (`src/gui/styles/qstylefactory.cpp:121-180`). For unmatched keys it asks the plugin loader (`QFactoryLoader` on `QStyleFactoryInterface_iid` with the `/styles` subdirectory, `src/gui/styles/qstylefactory.cpp:85-86`, load at `:169-175`). The created style's object name is set to the key (`:177-178`).
- Q4.4.4 GTK style construction and GTK load (the one path that touches GTK at run time):
  1. `QGtkStyle` constructor passes a `QGtkStylePrivate` to `QCleanlooksStyle` (`src/gui/styles/qgtkstyle.cpp:189-191`).
  2. `QGtkStyle::polish(QApplication*)` calls `QCleanlooksStyle::polish(app)` first, then, if `app->desktopSettingsAware()` and `isThemeAvailable()`, sets the system palette to `standardPalette()`, sets the system font to `getThemeFont()`, applies the custom palette hash, and installs file-dialog hooks (`src/gui/styles/qgtkstyle.cpp:324-340`).
  3. `QGtkStylePrivate::init()` calls `resolveGtk()` then `initGtkWidgets()` (`src/gui/styles/qgtkstyle_p.cpp:286-290`).
  4. `resolveGtk()` opens the library with `QLibrary("gtk-x11-2.0", 0, 0)` and `ImprovedSearchHeuristics`, so it loads `libgtk-x11-2.0.so.0`, and resolves `gtk_*` and `gdk_*` symbols into static function pointers, one `resolve()` call per symbol (`src/gui/styles/qgtkstyle_p.cpp:312-318`, the list continues to about line 380). The function-pointer typedefs are in `src/gui/styles/qgtkstyle_p.h` (e.g. `Ptr_gtk_init` at `:139`, `Ptr_gtk_style_attach` at `:141`, paint typedefs at `:189-201`).
  5. `initGtkWidgets()` refuses to run when setuid/setgid (`src/gui/styles/qgtkstyle_p.cpp:491-505`), reads the theme name through `getThemeName()` (`:507-508`), refuses the GTK "Qt"/"Qt4" engine names (`:510-516`), calls `gtk_init(NULL, NULL)` with the Qt X error handler saved and restored (`:518-521`), creates a popup `GtkWindow` and realizes it (`:524-527`), then builds a map of widget paths (`GtkWindow`, `GtkButton`, `GtkEntry`, ...) (`QGtkStylePrivate::gtkWidgetMap()`, `src/gui/styles/qgtkstyle_p.h:485-497`).
  6. Theme-change handling: when `getThemeName()` returns a different name, it resets the system palette and font, re-runs `initGtkWidgets()` and `applyCustomPaletteHash()` (`src/gui/styles/qgtkstyle_p.cpp:836-843`). Triggered from the event filter (see `src/gui/styles/qgtkstyle_p.cpp:265-266` for the filter's call site).
  7. `isThemeAvailable()`: when false, every draw call falls back to the Cleanlooks implementation (`src/gui/styles/qgtkstyle.cpp:680-685` shows the pattern in `drawPrimitive`; the same pattern appears in other draw entry points).
- Q4.4.5 Drawing: `QGtkStyle::drawPrimitive()` (`src/gui/styles/qgtkstyle.cpp:680`) and the other `draw*` overrides build a `QGtkPainter` on the target `QPainter` (`src/gui/styles/qgtkstyle.cpp:693`, `:1271`). `QGtkPainter::paintBox()` and related methods call `QGtkStylePrivate::gtk_paint_box(style, pixmap_window, state, shadow, rect, widget, part, x, y, w, h)` into an offscreen pixmap (`DRAW_TO_CACHE` macro, `src/gui/styles/qgtkpainter.cpp:107-110`; call at `:315`) and cache the result in `QPixmapCache` keyed by a string (`src/gui/styles/qgtkpainter.cpp:249`, `:264`, `:314`, `:326`). `gtk_paint_box_gap` at `:250`, `gtk_paint_hline` at `:368`.
- Q4.4.6 Palette: the GTK style does not draw color; it feeds `QPalette` and lets GTK's own drawing engine render the widgets (the GTK engine is whatever the GTK 2 gtkrc selects; this is GTK-side, see `gtk2` study for engine detail).
- Q4.4.7 Built-in non-GTK styles draw directly with QPainter. Helpers in `src/gui/styles/qstylehelper.cpp` (`uniqueName` at `:62`, `dpiScaled` at `:82`, `drawDial` at `:213`, `drawBorderPixmap` at `:323`).
- Q4.4.8 Qt stylesheets (`.qss` text) are handled by `QStyleSheetStyle` (`src/gui/styles/qstylesheetstyle.cpp`, 5906 lines; `QStyleSheetStyle::QStyleSheetStyle(QStyle *base)` at `:2613`, `polish(QWidget*)` at `:2672`, `styleSheetPalette` at `:5855`). It wraps a base QStyle and overrides per widget. Internals not studied.

## 5. Extension and integration points
- Q4.5.1 Style plugin interface: `QStyleFactoryInterface` with IID `"com.trolltech.Qt.QStyleFactoryInterface"` (`src/gui/styles/qstyleplugin.h:61`, declaration `:63`). Plugin base class `QStylePlugin : QObject, QStyleFactoryInterface` (`src/gui/styles/qstyleplugin.h:65`). Subclasses implement `keys()` (`:73`) and `create(key)` (`:74`). Plugins are exported with `Q_EXPORT_PLUGIN2()` (`src/gui/styles/qstyleplugin.cpp:59`, `:97`).
- Q4.5.2 Plugin discovery: `QFactoryLoader(QStyleFactoryInterface_iid, "/styles", CaseInsensitive)` (`src/gui/styles/qstylefactory.cpp:85-86`). Search directories come from the library paths, which include `QT_PLUGIN_PATH` entries and the application path (`src/corelib/kernel/qcoreapplication.cpp:2536-2550`). The `libraryPath` setting from the Trolltech settings file also adds library paths (`src/gui/kernel/qapplication_x11.cpp:2618-2624`).
- Q4.5.3 Platform-plugin interface: `QGuiPlatformPluginInterface` with IID `"com.nokia.qt.QGuiPlatformPluginInterface"` (`src/gui/kernel/qguiplatformplugin_p.h:73-79`), loaded from subdirectory `/gui_platform` (`src/gui/kernel/qguiplatformplugin.cpp:98-101`). A platform plugin can override `styleName()` (`src/gui/kernel/qguiplatformplugin_p.h:91`). This is the hook used to pick the default style from a desktop environment.
- Q4.5.4 Private-header coupling for GTK: `src/gui/styles/qgtkstyle_p.h` includes `<private/qcleanlooksstyle_p.h>` and then `<gtk/gtk.h>` (`src/gui/styles/qgtkstyle_p.h:66`, `:69`). The GTK 2 headers are therefore needed at compile time, but the Qt binary does not link `libgtk` directly; the symbols are resolved at run time (`src/gui/styles/qgtkstyle_p.cpp:312-318`). The `#undef signals` before the GTK include is a documented workaround (`src/gui/styles/qgtkstyle_p.h:68`).
- Q4.5.5 Qt ABI coupling: the style is built into libQtGui (no separate soname). `QGtkStyle` is exported with `Q_GUI_EXPORT` (`src/gui/styles/qgtkstyle.h:61`) and is used by `qapplication_x11.cpp` through `inherits("QGtkStyle")` string checks (`src/gui/kernel/qapplication_x11.cpp:917`, `:1287`), not by type. The GTK library version is fixed to the `gtk-x11-2.0` soname with `.so.0` suffix (`src/gui/styles/qgtkstyle_p.cpp:314`).
- Q4.5.6 Build-time coupling: `pkg-config gtk+-2.0 >= 2.10 atk` (`configure:6412`).
- Q4.5.7 Installed locations for style plugins: `UNVERIFIED: install prefix for plugins/styles was not traced in this study (qmake install rules not read).`

## 7. Facts of note
- Q4.7.1 The GTK style is GTK 2 only: it loads `libgtk-x11-2.0.so.0` and uses `GtkStyle`/`GdkColor` types (`src/gui/styles/qgtkstyle_p.cpp:314-318`, `src/gui/styles/qgtkstyle_p.h:69`). No GTK 3 or GTK 4 path exists in this tree.
- Q4.7.2 Under setuid/setgid the GTK path is disabled with a warning (`src/gui/styles/qgtkstyle_p.cpp:491-505`).
- Q4.7.3 The GTK engine named `Qt`/`Qt4` is refused to avoid recursion (`src/gui/styles/qgtkstyle_p.cpp:509-515`).
- Q4.7.4 `QApplication::style()` falls back to the first style that can be created when the desired key fails (`src/gui/kernel/qapplication.cpp:1466-1472`).
- Q4.7.5 Comment in the X11 settings code: "### Fix properly for 4.6" around the GTK bypass of Qt palette/font settings (`src/gui/kernel/qapplication_x11.cpp:916-918`, `:924-925`). When the GTK style is active, the settings file's palette and font are not applied (`:917-918`, `:925`).
- Q4.7.6 Comment in the GTK style: custom fonts and palettes via QtConfig are "intentionally not supported" when GTK settings are used (`src/gui/styles/qgtkstyle.cpp:329-331`).
- Q4.7.7 The GNOME default style is "GTK+" only if that key is registered (`src/gui/kernel/qguiplatformplugin.cpp:165-171`); otherwise cleanlooks (when xrender is on, `:173-174`).
- Q4.7.8 `QT_STYLE_OVERRIDE` is honoured only in internal builds (`src/gui/kernel/qapplication.cpp:1451-1452`).
- Q4.7.9 License: LGPL. Source headers say "Copyright (C) 2015 The Qt Company Ltd." (`LICENSE.LGPL` header). Qt-licensing contact cited in the same file.
