# Test environments and checks

Start the persistent interactive nested session with `make test-env`. It retains its private `.test-state/nested` preferences/cache and leaves popups closed. Nested shortcuts use Ctrl+Alt: Ctrl+Alt+Q opens foot, Ctrl+Alt+Space opens the launcher, and Ctrl+Alt+W opens the wallpaper picker. Workspace focus uses Ctrl+Alt+number; moving a window and following it uses Ctrl+Shift+number; moving it without following uses Ctrl+number. Shift actions use Ctrl+Shift without Alt; Ctrl+Alt+Shift would trigger the host language toggle. Ctrl+Alt+Escape exits gracefully from any submap. `make test-env-clean` resets private choices, profile selection, generated profiles, component settings, cache and other private home state, then reseeds the source manifest and clean default seed. It preserves all Theme definitions byte-for-byte, including imported and edited definitions. Host configuration/data and source files remain untouched. The root `make help` groups environment, check, and development targets.

`make test-env-persistent` names that same persistent session and storage
explicitly. It does not open a popup or reset preferences.

`test-env` starts only the interactive nested session. It performs launch
preflight checks but does not run automated checks or QML tests. The explicit
`test_open_picker=0` default keeps the wallpaper picker closed; open it with
Ctrl+Alt+W. From the picker, Enter or Choose theme opens the editor for the
selected wallpaper draft; Ctrl+T opens the editor directly for the selection.
It does not run the automated UI harness or close on a test deadline. `test-env-snapshot` is the
separate bounded readiness/frame/diagnostic check. Both retain private choices;
neither uses the host configuration.

Interactive environment targets:

- `make test-env`: persistent interactive nested session; popups closed, existing `.test-state/nested` preferences and cache retained.
- `make test-env-persistent`: explicit persistent entrypoint; same storage and behavior as `test-env`.
- `make test-import-themes`: regenerate matching reference Theme definitions in persistent private state, without opening a window, compiling a profile bundle, or selecting/activating a Theme. Unrelated/custom Theme IDs and all profile recipes remain untouched. Close a running persistent session first.
- `make test-env-fresh`: explicitly ephemeral interactive nested session; popups closed.
- `make test-env-apps`: ephemeral interactive launcher with the existing launcher behavior.
- `make test-env-snapshot`: persistent bounded capture that exits automatically.
- `make test-env-clean`: explicit reset of private choices, profile selection, generated profiles, component settings, cache and other private home state; reseeds the source manifest and clean default seed, and preserves all Theme definitions byte-for-byte, including imported and edited definitions. Host configuration/data and source files remain untouched.
- `make test-env-phantomat`: the same persistent private home/cache and interactive nested session as `make test-env`, with the Phantomat plugin loaded dormant. It waits on the compositor after readiness and exits when the session is closed. It depends on `make dev-build-phantomat`.

Automated checks use disposable state and run only when their Make target is requested. `make test-sandbox`, `make test-hypr-config`, `make test-qml`, `make test-theme-config`, and `make test-pipelines` are independent checks. The Hyprland parser uses a temporary HOME/XDG tree; Bubblewrap targets use their own ephemeral sandbox. `make test` is the explicit aggregate for script, sandbox, Hyprland, QML, theme/config and pipeline checks. Focused GUI checks include `make test-wallpaper`, `make test-motion`, `make test-launcher`, `make test-theme`, and `make test-profiles`. `make test-env-phantomat` is an interactive persistent session, not a bounded check; it shares the saved state used by `make test-env`.

Development targets are `make dev-stage`, `make dev-configure`, `make dev-import-themes`, `make dev-lint`, `make dev-verify-hypr`, `make dev-build-phantomat`, and `make dev-verify-phantomat`. `make dev-run` launches with the host display and is not sandboxed. Installed runtime helpers are in `scripts/`; development staging is `tools/scripts/stage-config`; checks and test-only helpers are in `tests/scripts/` under their original basenames. `make help` is the concise target reference.

## Running tests

Latest saving verification: the full suite passed 161 QML JUnit entries with no failures/skips. A separate persistent native Save and apply check and its restart restored the saved wallpaper/colors with unchanged committed-file hashes; existing private choices were preserved. See [the saving and persistent sandbox report](../.build/tests/reports/test-report-2026-10-08-064508.md).

`make test-env-fresh` runs the production Hyprland configuration in Bubblewrap. Edit `nested.conf` to choose graphics access, picker startup, palette startup, launcher, readiness deadline, artifact retention, and the exact directories shared with the test. It never silently retries outside the sandbox.

Keyboard input is explicit in this private environment: `test_qt_input_method=compose` sets `QT_IM_MODULE=compose`. `test_qtpaths` resolves the installed Qt plugin directory, and a missing configured plugin fails before startup. This tests local keyboard input and clipboard focus without depending on compositor or host IME services; it does not verify Wayland text-input protocol or external IME integration. Production input-method selection is unchanged. Unexpected Quickshell diagnostics remain fatal; no text-input warning suppression or new allowlist is used.

In the focused nested window, the native `Ctrl+Alt+Escape` binding gracefully exits the nested Hyprland session from any submap; the launcher then cleans up Quickshell and Hyprpaper. Nested shortcut settings live in `hypr/user/nested.lua`. `hypr/nested.lua` applies the profile overrides before production bindings are imported; production keeps Super and has no test exit binding. Persistent test preferences remain saved after exit.

Each run gets a private home. Interactive ephemeral targets and all automated GUI checks use in-memory ephemeral state. `test-env` and `test-env-snapshot` retain dedicated storage under the configured `test_state_directory`:

```text
/home/test/
├── .config/
├── .cache/
└── .local/
    ├── share/
    └── state/
```

`XDG_RUNTIME_DIR` is `/run/test`, and D-Bus runs a private session. Host HOME, cache, state, full session bus, audio sockets, Hyprland sockets, and network access are not shared. Interactive sessions and the explicit real-launch check expose the host systemd user-manager API through a filtered `xdg-dbus-proxy`, solely for native app2unit scope registration. Other automated checks and theme import expose no manager API. The host bus socket and manager private socket are not mounted. Read-only system directories, the single parent Wayland socket, project wallpapers, and GPU render nodes are listed explicitly in the configuration. The parent Wayland socket displays the nested window; this is trusted development isolation with a shared display/GPU, not a VM or a security boundary against hostile code. The proxy restricts service names, not systemd method arguments: test code can access the manager API, so only trusted applications should be launched.

Every run stages the actual `ui-shell/{scripts,quickshell,themes,profiles,default,config.ini,hypr}` package at the private `$XDG_CONFIG_HOME/ui-shell`. Staging replaces `default/` with the clean seed and seeds `themes/default/config.ini` and `profiles/default/profile.ini` only when absent. Runtime consumers use resolved command roles and generated native QML/Lua paths in that package. `/project` is a fresh writable build/test harness, not the production runtime root; `/source` remains read-only. The test configuration explicitly exposes read-only external asset directories; the staged `default/` seed is writable private data. Wallpaper folders come from the manifest's `[wallpaper_folders]` list, not UI or script constants; adding a manifest entry does not automatically expose a host path through Bubblewrap.

Persistent mode mounts its dedicated `home/` at `/home/test`. Its private `config.ini`, clean `default/` seed, Theme definitions, `profiles/` recipes and scoped settings are bound into a fresh ephemeral runtime package. Each schema-2 recipe contains its wallpaper choices and full color data; no registry sidecar is mounted. The startup recipe is `profiles/default/profile.ini`. Generated projections and installed code are fresh on every run, while user preferences and cache persist. The manifest remains schema 2 and wallpaper folders come only from `[wallpaper_folders]`; there is no legacy migration for unreleased config or scoped settings. Saved wallpaper selections require explicit folder IDs, and missing or unknown IDs fail without inference. Private retained choices from an older recipe schema require an explicit reset with `make test-env-clean`; this preserves imported Theme definitions. No host preferences are read or migrated.

Exiting always tears down the PID namespace, children, runtime sockets, bus, and copied code. Ephemeral mode also discards its home and profile recipes; persistent mode retains its private home and recipes. Cleanup waits for the log writer, checks that no tagged test processes remain, and compares protected host files against their pre-run hashes. `test_logs=keep` retains logs, QML JUnit reports, profiler `.qtd` traces, and diagnostic frames including `frame.png`, `frame-applied.png`, `frame-launcher.png`, `frame-launcher-info.png`, `frame-launcher-settings.png`, `frame-launcher-dropdown.png`, `frame-picker-info.png`, `frame-picker-settings.png`, `frame-launcher-error.png`, `frame-settings-error.png` and `frame-picker-error.png` in a unique printed `/tmp/ui-shell-test.*` directory; `discard` removes diagnostics too. Your real `.config`, `.cache`, and `.local` are never mounted.

## Application launcher checks

The private launcher catalog currently contains system entries plus test fixtures only. Host user desktop entries and custom host `XDG_DATA_DIRS` are not imported. This can omit user-installed AppImages, JetBrains tools and local shortcuts when comparing the nested test with a host launcher. Production Quickshell discovers them through the real session's XDG directories; isolation, not an additional application filter, accounts for that test-only gap.

`make test-env-apps` opens the launcher in an ephemeral private nested session with real app launches enabled. `make test-env` and `make test-env-persistent` use the same test-only runner while retaining private choices. Production `AppRunner.qml` and `config/AppLauncher.qml` remain unchanged: only the staged private QML runner settings point to `tests/scripts/run-app2unit`. Native app2unit still receives desktop-entry IDs and owns Exec parsing and terminal handling. Its private PATH intercepts only `systemd-run`; the shim uses a systemd-only proxy connection, restores the application's private runtime, session bus and original PATH, and acknowledges scope registration promptly instead of waiting for application exit. Each run owns a unique slice and recorded scopes; teardown stops only those units and checks the host manager environment digest. No host environment import, graphical target change, UWSM setup or production IPC is added. Apps still lack host networking, audio, home files and private host desktop services by design.

`make test-app-launch` is the bounded real GUI integration check. It exercises the unchanged production AppRunner with the staged test configuration, launches a native desktop entry into a real nested window, verifies private HOME/XDG/PID/mount/network/D-Bus and scope membership, then checks a missing entry reports nonzero/stderr failure. The app remains alive after runner handoff. It captures `frame-app-launch.png`, closes automatically and verifies no tagged processes or owned active units remain. Inspect the printed artifact directory's `app-runner.log`, `application-env.log`, `app-clients.log` and frame. `make test-app2unit` retains the independent host-registration-before-Bubblewrap proof below.

`make test-session-close` launches that real application, then sends the host's normal close request to the exact nested window. It verifies that the sandbox exits within `test_exit_seconds`, that the window is gone, and that the ordinary post-run unit/process/host-state checks pass. It does not force-kill the compositor to simulate a window close.

Interactive sessions still use `start-hyprland`. Every sandbox child inherits a unique `UI_SHELL_TEST_PREFIX=ui-shell-test-<run-id>`; `test_process_prefix` is explicit in `nested.conf`. The harness tracks the original compositor's host window by its discovered PID, not a monitor name/class or an arbitrary focused window. Closing that window runs `tests/scripts/close-session`, which enumerates and signals only processes carrying the exact run prefix, including the watchdog, compositor, shell, private bus, wallpaper service and launched apps. A watchdog restart is not adopted as a new session. `test_shutdown_signal=KILL` is the explicit fast-iteration default; set it to `TERM` for a grace period bounded by `test_cleanup_seconds`, followed by KILL. Fast teardown can discard unsaved application work. Persistent committed preferences and Theme definitions remain retained; no cleanup resets them. Run-owned scopes/slice, proxy and log writer are then cleaned and verified with bounded waits. Nested Hyprland explicitly writes debug/warning/error output to its retained `hypr/<instance>/hyprland.log` and stdout to `launcher.log` in the printed `/tmp/ui-shell-test.*` artifact directory; production logging is unchanged. Production session startup and AppRunner are unchanged.

`make test-launcher` remains a separate native dry-run check: it covers catalog and panel behavior, search focus, candidate selection, icon visibility/empty image source, failure presentation and four opens/closes with one retained panel. Contextual popup and scoped-settings cases retain their diagnostic frames. Non-graphical `make test-sandbox`, theme import, and this dry-run fixture do not expose the manager proxy.

The automated launcher check uses real `app2unit --test` from the configured PATH: it verifies desktop-entry filename handling, quoted arguments, `%c`, and the service-mode systemd command without starting an application. This does not prove real user-service creation or terminal launching. `xdg-terminal-exec` is required by app2unit for terminal entries. `test_icon_theme` declares the sandbox icon theme explicitly via `QS_ICON_THEME`; no host Qt configuration is mounted. Diagnostics include `launcher-test.log` and `frame-launcher.png`.

`make test-app2unit` runs `tests/scripts/check-app2unit-scope` as a standalone retained smoke test; it is not part of `test-env` or the launcher GUI check. Host-side app2unit registers a uniquely named scope and slice, then its command enters Bubblewrap. The application has private HOME, XDG directories, session D-Bus, PID, mount and network namespaces. No host manager socket or host session bus is mounted inside. The check verifies the host manager environment is unchanged and that run-owned units and tagged processes are gone. `test_app2unit_seconds` explicitly bounds the run. There is no private UWSM or journald setup. Registering before entering the private PID namespace avoids the direct manager-socket failure (`No data available`) observed with a hidden host peer. This is trusted development isolation with read-only installed system files, not a VM. `make test-launcher` remains a dry-run for app2unit and does not start an application.

Launch-progress checks delay the configured real runner only in the private fixture. They capture `frame-launcher-starting.png`, verify one row-local pulsing dot and no visible Starting footer, and compare panel/search/list/row/label bounds while pending. Error presentation preserves the card height; successful handoff closes once and reopening has no stale indicators. The test timer rejects nested ticks during native keyboard event processing.

`make test` also covers AppSearch ranking/filtering/reindexing with a nongating 1,000-entry timing diagnostic. `tst_LauncherOutput.qml` runs against the explicit default, a generated named-output override, and a generated index override. It verifies exact-target resolution and refusal to substitute an unavailable output; invalid renderer input must preserve the prior policy. Generated changes remain inside the writable test copy, and the host launcher-output file is protected by the before/after hash check.

## Keeping a test wallpaper across restarts

### Try every reference Theme

```sh
make test-import-themes      # import palette definitions; profile recipes stay unchanged
make test-env-persistent     # nested session only, with popups closed
# Ctrl+Alt+W, choose a wallpaper, Enter, then select a palette definition.
# Ctrl+Enter saves the recipe and activates its complete generation; Ctrl+Alt+Escape exits.
make test-env-persistent     # inspect the retained wallpaper/theme after restart
```

The high-level importer uses the configured runtime command roles and `paths.themes`.
It converts each reference variant to one flat `config.ini` at
`themes/SLUG-VARIANT/config.ini`. Imported definitions contain palette colors only. Import creates no
profile recipe, selection, or activation. The picked
wallpaper remains a draft until final Save and apply.

`tests/nested.conf` explicitly owns `test_theme_reference`, plus
`test_theme_positive`, `test_theme_warning` and `test_theme_negative` source
fields. Their defaults are `refs/100-themes`, `green`, `yellow` and `red`. These are declared mappings, not
guesses about terminal-color semantics; review previews before applying.
Theme definitions persist under private `themes/`; profile recipes persist
under private `profiles/`. Import never changes the active profile or live desktop.
Retries regenerate matching reference definitions, replacing local edits to those IDs when reference output differs. Unrelated/custom Theme IDs and all profile recipes remain unchanged. References are mounted read-only.
Import is an explicit step, never ordinary startup or an automated UI side effect.

### Restart or reset private state

```sh
make test-env           # nested session only; open the picker on demand, exit with Ctrl+Alt+Escape
make test-env-persistent # same private home/cache/choice, latest project code
make test-env-snapshot  # bounded restart, capture frame/logs, close automatically
make test-env-clean     # reset private choices/cache; keep Theme definitions; host/source untouched
```

The default storage is `.test-state/nested/`: `home/` owns its `.config`, `.cache`, and `.local`. The private `.config/ui-shell/config.ini`, Theme definitions, schema-2 profile recipes and scoped settings survive. Each recipe records wallpaper selections and full palette data. The first persistent run seeds the manifest, clean default seed, and absent default Theme/profile stores. Subsequent `test-env` runs retain those choices and reusable compiled cache generations while staging fresh code. Targets choose their state mode explicitly; the direct nested helper's configuration default remains ephemeral. Automated checks use ephemeral state so scripted changes do not overwrite interactive choices.

Persistent sessions mount the private configuration **directory**, so Save and apply can atomically replace `config.ini` and retain standalone `profiles/`. `test_ephemeral_config_parts` overlays fresh `scripts/`, `quickshell/`, and `hypr/` directories for each run. The host home remains unavailable; saving needs no relaxation of isolation.

The picker and editor retain wallpaper and palette choices as a draft. Advancing, loading a saved profile, Back, or cancelling must not change live wallpaper, saved selections, active palette, or persisted profile; only final Save and apply commits the bundle and refreshes colors. Reopening the persistent session restores the selected bundle and regenerates QML from retained inputs/cache. `shell-palettes.log` records startup output palettes, `global-palette.log` the startup global palette and `wallpaper-startup.log` the native assignment. A display override changes that display's QML palette; wallpaper-mode global colors still follow `palette_source` in `hypr/user/monitors.lua`.

Cleaning resets private choices, generated profiles, component settings, cache and other private home state, then immediately reseeds the source manifest, replaces `default/` with the clean seed, and creates missing default Theme/profile stores. It reads the saved manifest's Theme storage address without loading the selected profile; stale profile selections do not block reset. Every Theme definition is retained byte-for-byte, including imported definitions and user edits. If storage was renamed, the retained definitions move to the source-default Theme directory. Retained definitions take precedence over checked-in palettes; reset never validates or regenerates them. Cleaning does not remove project configuration or retained diagnostic artifacts. Storage is restricted to `.test-state/<profile>` and carries an owner marker. A sibling lock prevents simultaneous sessions and cleaning while a session is active; the harmless lock file remains after cleaning. Missing or redirected manifest/Theme storage fails before existing state changes.

`make test-wallpaper` waits for a valid output, Hyprpaper surface, bar, and (if configured) picker. It rejects configuration errors, unexpected Quickshell warnings/errors, and blank captured frames. Its test-only host checks saved-tile opening, candidate movement without side effects, scoped failures, and the wallpaper draft entry flow. The fixture verifies that advancing has no live/persisted wallpaper or palette effects, then final Save and apply changes the image and palette together. The strict gate passes with the private environment's explicit Compose input method. The harness is copied into the private shell root because Quickshell forbids imports outside a config root. All mutations happen in the private copy. The session closes automatically; inspect saved frames and logs after every visual run. `make test-env` stays open for manual testing and never opens the picker automatically with the shipped startup configuration.

Startup prepares the selected profile's complete native bundle before the Hyprland UI starts, including on a cold cache; frame capture therefore sees prepared palette and wallpaper targets. The configured `[bootstrap] profileModule` path is atomically linked to the generated Quickshell module in XDG cache, and `GeneratedRuntime.qml` imports through that in-root path. Generated bundle files remain in cache; no consumer reconstructs their location. The private bus has no auto-activation service directories; Qt portal integration is explicitly disabled, and GSettings uses its memory backend. No host desktop services are started or reused.

`make test-sandbox` checks filesystem, XDG, D-Bus, PID, and network isolation without opening a window, then validates both copied Hyprland entrypoints and all shell QML files. Qt Quick Test runs `tst_ControlState.qml` offscreen: border precedence, distinct light/dark state colors, selection stronger than hover, neutral outline surfaces, committed-value hover, independent focus, and solid-action text contrast. `tst_WallpaperTile.qml` tests real component interaction and rendered pixels. An unmodified copy of this service-free tile is placed at the same relative import depth in the private shell tree, avoiding the wallpaper module's sibling Quickshell singleton; its actual theme/config/control imports are retained, with no mocked state or services. Timestamped JUnit XML survives under the printed artifact directory's `build/tests/reports/junit/`. The complete picker still runs in the live `qs` harness because its plugins are embedded in that binary. The sandbox also checks real Matugen cache reuse, all current palette renderers, exact-output persistence, and generated QML target metadata. `make test` runs these plus Bash syntax checks. These need an existing Wayland session because the same explicit parent socket mount is checked.

`make test-env-phantomat` uses the same persistent private home/cache and nested-session lifecycle as `make test-env`, with the locally built Phantomat plugin loaded dormant. Startup remains on native dwindle; Canvas and its HUD stay closed until requested. `Ctrl+Shift+F5` toggles Canvas for the focused real workspace, and `Ctrl+Shift+O` toggles its HUD only while that workspace's Canvas renderer is active. Canvas state belongs to each real workspace: switching uses an explicit slide transition in both directions, retains the outgoing Canvas renderer, and preserves each client's geometry and saved camera; no client is re-tiled, resized, or moved for the handoff. Explicitly disabling Canvas or unloading the plugin restores native layout. Entering Canvas keeps the focused client selected and animates the camera to center it. Fullscreen temporarily suspends rendering without clearing the workspace's Canvas mode, which resumes when fullscreen ends. Real workspace and group bindings remain available alongside the F1–F4 layout binds. While Canvas is not rendering, shared focus, move, maximize, pin, and window-cycle bindings route to their native Hyprland actions. The workspace bar remains unchanged. Editable camera and Navigator settings live in `hypr/user/canvas.lua`; palette wiring lives in `hypr/phantomat.lua`. Production remains Super-based with the plugin disabled. Nested shortcut settings are explicit in `hypr/user/nested.lua`.

`hypr/user/canvas.lua` explicitly enables `canvas.remember_overview`: leaving a workspace in overview restores its camera, zoom, search and selected live client on return. A closed HUD stays closed; fresh Canvas activation still starts at 100%. Set the option to `false` for the previous HUD-closed return behavior. This state lasts for the compositor session only and is independent of `remember_layout`; disabling Canvas clears it. Native workspaces do not inherit the HUD or its input overrides.

Canvas camera/HUD motion uses the same `speed = 2` and `quick-out` curve as the Hyprland window-entry animation. The bottom minimap shares the search HUD's eased progress and slides up from the lower edge as it fades in; its arrange hit target follows the moving map. On HUD exit, the temporary minimap hold is cleared so its map and adjacent Arrange square fade together with that transition. Ordinary place-travel flashes retain their brief independent display.

During real workspace switches, overview chrome fades with native workspace visibility and opacity. The selected outline uses the client's signed workspace offset and finite camera clip, so clients do not slide into a stationary outline. Outgoing renderers reuse their last HUD textures and weak window references only until the native transition finishes; search/input ownership ends immediately. The existing HUD-toggle animation is unchanged.
