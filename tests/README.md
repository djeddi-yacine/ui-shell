# Test environments and checks

Start the persistent interactive nested session with `make test-env`. It retains its private `.test-state/nested` preferences/cache and leaves popups closed. Nested shortcuts use Alt+Multi_key: Alt+Multi_key+Q opens foot, Alt+Multi_key+Space opens the launcher, and Alt+Multi_key+W opens the wallpaper picker. Workspace focus uses Alt+Multi_key+number; moving a window and following it uses Alt+Multi_key+Shift+number; moving it without following uses Alt+Multi_key+Ctrl+number. Alt+Multi_key+Shift stays clear of the host language toggle. Alt+Multi_key+Escape exits gracefully from any submap. `make test-env-clean` resets private choices, profile selection, generated profiles, component settings, cache and other private home state, then reseeds the source manifest and clean default seed. It preserves all Theme definitions byte-for-byte, including imported and edited definitions. Host configuration/data and source files remain untouched. The root `make help` groups environment, check, and development targets.

`make test-env` is the only interactive entrypoint and has every feature on: the wallpaper picker, launcher, control tuning, the audio panel on the HOST PipeWire socket (changes are real; `UI_SHELL_HOST_PIPEWIRE=0` keeps audio private), the screen-recording panel, and the Phantomat plugin (built on demand, loaded when the build works). The separate `-persistent`, `-fresh`, `-apps`, `-audio` and `-phantomat` entrypoints were removed.

`test-env` starts only the interactive nested session. It performs launch
preflight checks but does not run automated checks or QML tests. The explicit
`test_open_picker=0` default keeps the wallpaper picker closed; open it with
Alt+Multi_key+W. From the picker, Enter or Choose theme opens the editor for the
selected wallpaper draft; Ctrl+T opens the editor directly for the selection.
It does not run the automated UI harness or close on a test deadline. `test-env-snapshot` is the
separate bounded readiness/frame/diagnostic check. Both retain private choices;
neither uses the host configuration.

Interactive environment targets:

- `make test-env`: the interactive nested session with everything enabled (see above); popups closed, existing `.test-state/nested` preferences and cache retained.
- `make test-import-themes`: regenerate matching reference Theme definitions in persistent private state, without opening a window, compiling a profile bundle, or selecting/activating a Theme. Unrelated/custom Theme IDs and all profile recipes remain untouched. Close a running persistent session first.
- `make test-env-snapshot`: persistent bounded capture that exits automatically.
- `make test-env-clean`: explicit reset of private choices, profile selection, generated profiles, component settings, cache and other private home state; reseeds the source manifest and clean default seed, and preserves all Theme definitions byte-for-byte, including imported and edited definitions. Host configuration/data and source files remain untouched.

Automated checks use disposable state and run only when their Make target is requested. `make test-sandbox`, `make test-hypr-config`, `make test-qml`, `make test-theme-config`, and `make test-pipelines` are independent checks. The Hyprland parser uses a temporary HOME/XDG tree; Bubblewrap targets use their own ephemeral sandbox. `make test` is the explicit aggregate for script, sandbox, Hyprland, QML, theme/config and pipeline checks. Focused GUI checks include `make test-wallpaper`, `make test-motion`, `make test-launcher`, `make test-theme`, and `make test-profiles`. `make test-env-phantomat` is an interactive persistent session, not a bounded check; it shares the saved state used by `make test-env`.

Development targets are `make dev-stage`, `make dev-configure`, `make dev-import-themes`, `make dev-lint`, `make dev-release`, `make dev-check-update`, `make dev-verify-hypr`, `make dev-build-phantomat`, and `make dev-verify-phantomat`. `make dev-run` launches with the host display and is not sandboxed. Installed runtime helpers are in `scripts/`; development staging is `tools/scripts/stage-config`; checks and test-only helpers are in `tests/scripts/` under their original basenames. `make help` is the concise target reference.

## Running tests

Latest saving verification: the full suite passed 161 QML JUnit entries with no failures/skips. A separate persistent native Save and apply check and its restart restored the saved wallpaper/colors with unchanged committed-file hashes; existing private choices were preserved. See [the saving and persistent sandbox report](../.build/tests/reports/test-report-2026-10-08-064508.md).

`make test-env` runs the production Hyprland configuration in Bubblewrap. Edit `nested.conf` to choose graphics access, picker startup, palette startup, launcher, readiness deadline, artifact retention, and the exact directories shared with the test. It never silently retries outside the sandbox.

Keyboard input is explicit in this private environment: `test_qt_input_method=compose` sets `QT_IM_MODULE=compose`. `test_qtpaths` resolves the installed Qt plugin directory, and a missing configured plugin fails before startup. This tests local keyboard input and clipboard focus without depending on compositor or host IME services; it does not verify Wayland text-input protocol or external IME integration. Production input-method selection is unchanged. Unexpected Quickshell diagnostics remain fatal; no text-input warning suppression or new allowlist is used.

In the focused nested window, the native `Alt+Multi_key+Escape` binding gracefully exits the nested Hyprland session from any submap; the launcher then cleans up Quickshell and Hyprpaper. Nested shortcut settings live in `hypr/default/nested.lua`. `hypr/nested.lua` applies the profile overrides before production bindings are imported; production keeps Super and has no test exit binding. Persistent test preferences remain saved after exit.

Each run gets a private home. Interactive ephemeral targets and all automated GUI checks use in-memory ephemeral state. `test-env` and `test-env-snapshot` retain dedicated storage under the configured `test_state_directory`:

```text
/home/test/
├── .config/
├── .cache/
└── .local/
    ├── share/
    └── state/
```

`make test-env-host` runs on the real session under `bwrap`, which sets no-new-privileges: `gsr-kms-server` loses its `cap_sys_admin` file capability, so screen recordings made there are black (audio is fine). Check recording on a normal session instead.

`XDG_RUNTIME_DIR` is `/run/test`, and D-Bus runs a private session. Host HOME, cache, state, full session bus, audio sockets, Hyprland sockets, and network access are not shared. Interactive sessions and the explicit real-launch check expose the host systemd user-manager API through a filtered `xdg-dbus-proxy`, solely for native app2unit scope registration. Other automated checks and theme import expose no manager API. The host bus socket and manager private socket are not mounted. Read-only system directories, the single parent Wayland socket, project wallpapers, and GPU render nodes are listed explicitly in the configuration. The parent Wayland socket displays the nested window; this is trusted development isolation with a shared display/GPU, not a VM or a security boundary against hostile code. The proxy restricts service names, not systemd method arguments: test code can access the manager API, so only trusted applications should be launched.

The update system is covered by `make test-update`, `test-activator`, `test-crash`, `test-migrations` and `test-crossing`. Every run stages the actual `ui-shell/{scripts,shell,themes,profiles,default,manifest.ini,settings.ini,RELEASE,hypr}` package at the private `$XDG_CONFIG_HOME/ui-shell`, then builds the generated Quickshell tree at `$XDG_CACHE_HOME/ui-shell/runtime`; test shells and `/project/shell` read that tree. Staging replaces `default/` with the clean seed and seeds `themes/default/config.ini` and `profiles/default/profile.ini` only when absent. Runtime consumers use resolved command roles and generated native QML/Lua paths in that package. `/project` is a fresh writable build/test harness, not the production runtime root; `/source` remains read-only. The test configuration explicitly exposes read-only external asset directories; the staged `default/` seed is writable private data. Wallpaper folders come from the manifest's `[wallpaper_folders]` list, not UI or script constants; adding a manifest entry does not automatically expose a host path through Bubblewrap.

Persistent mode mounts its dedicated `home/` at `/home/test`. Its private `settings.ini`, clean `default/` seed, Theme definitions, `profiles/` recipes and scoped settings are bound into a fresh ephemeral runtime package. Each schema-2 recipe contains its wallpaper choices and full color data; no registry sidecar is mounted. The startup recipe is `profiles/default/profile.ini`. Generated projections and installed code are fresh on every run, while user preferences and cache persist. The manifest remains schema 2 and wallpaper folders come only from `[wallpaper_folders]`; there is no legacy migration for unreleased config or scoped settings. Saved wallpaper selections require explicit folder IDs, and missing or unknown IDs fail without inference. Private retained choices from an older recipe schema require an explicit reset with `make test-env-clean`; this preserves imported Theme definitions. No host preferences are read or migrated.

Exiting always tears down the PID namespace, children, runtime sockets, bus, and copied code. Ephemeral mode also discards its home and profile recipes; persistent mode retains its private home and recipes. Cleanup waits for the log writer, checks that no tagged test processes remain, and compares protected host files against their pre-run hashes. `test_logs=keep` retains logs, QML JUnit reports, profiler `.qtd` traces, and diagnostic frames including `frame.png`, `frame-applied.png`, `frame-launcher.png`, `frame-launcher-info.png`, `frame-launcher-settings.png`, `frame-launcher-dropdown.png`, `frame-picker-info.png`, `frame-picker-settings.png`, `frame-launcher-error.png`, `frame-settings-error.png` and `frame-picker-error.png` in a unique printed `/tmp/ui-shell-test.*` directory; `discard` removes diagnostics too. Your real `.config`, `.cache`, and `.local` are never mounted.

## Application launcher checks

The private launcher catalog currently contains system entries plus test fixtures only. Host user desktop entries and custom host `XDG_DATA_DIRS` are not imported. This can omit user-installed AppImages, JetBrains tools and local shortcuts when comparing the nested test with a host launcher. Production Quickshell discovers them through the real session's XDG directories; isolation, not an additional application filter, accounts for that test-only gap.

`make test-env` uses the test-only runner that allows real app launches while retaining private choices. Production `AppRunner.qml` and `config/AppLauncher.qml` remain unchanged: only the staged private QML runner settings point to `tests/scripts/run-app2unit`. Native app2unit still receives desktop-entry IDs and owns Exec parsing and terminal handling. Its private PATH intercepts only `systemd-run`; the shim uses a systemd-only proxy connection, restores the application's private runtime, session bus and original PATH, and acknowledges scope registration promptly instead of waiting for application exit. Each run owns a unique slice and recorded scopes; teardown stops only those units and checks the host manager environment digest. No host environment import, graphical target change, UWSM setup or production IPC is added. Apps still lack host networking, audio, home files and private host desktop services by design.

`make test-app-launch` is the bounded real GUI integration check. It exercises the unchanged production AppRunner with the staged test configuration, launches a native desktop entry into a real nested window, verifies private HOME/XDG/PID/mount/network/D-Bus and scope membership, then checks a missing entry reports nonzero/stderr failure. The app remains alive after runner handoff. It captures `frame-app-launch.png`, closes automatically and verifies no tagged processes or owned active units remain. Inspect the printed artifact directory's `app-runner.log`, `application-env.log`, `app-clients.log` and frame. `make test-app2unit` retains the independent host-registration-before-Bubblewrap proof below.

`make test-session-close` launches that real application, then sends the host's normal close request to the exact nested window. It verifies that the sandbox exits within `test_exit_seconds`, that the window is gone, and that the ordinary post-run unit/process/host-state checks pass. It does not force-kill the compositor to simulate a window close.

`UI_SHELL_HYPR_LOG=off|warn|debug|trace` (for example `UI_SHELL_HYPR_LOG=off make test-env`) sets what Hyprland and Aquamarine print to the terminal: `off` only errors, `warn` warnings and errors, `debug` the default, `trace` everything with their trace logging on. `launcher.log` and `hyprland.log` always keep the full output (`tests/scripts/filter-hypr-log`). Interactive sessions still use `start-hyprland`. Every sandbox child inherits a unique `UI_SHELL_TEST_PREFIX=ui-shell-test-<run-id>`; `test_process_prefix` is explicit in `nested.conf`. The harness tracks the original compositor's host window by its discovered PID, not a monitor name/class or an arbitrary focused window. Closing that window runs `tests/scripts/close-session`, which enumerates and signals only processes carrying the exact run prefix, including the watchdog, compositor, shell, private bus, wallpaper service and launched apps. A watchdog restart is not adopted as a new session. `test_shutdown_signal=KILL` is the explicit fast-iteration default; set it to `TERM` for a grace period bounded by `test_cleanup_seconds`, followed by KILL. Fast teardown can discard unsaved application work. Persistent committed preferences and Theme definitions remain retained; no cleanup resets them. Run-owned scopes/slice, proxy and log writer are then cleaned and verified with bounded waits. Nested Hyprland explicitly writes debug/warning/error output to its retained `hypr/<instance>/hyprland.log` and stdout to `launcher.log` in the printed `/tmp/ui-shell-test.*` artifact directory; production logging is unchanged. Production session startup and AppRunner are unchanged.

`make test-menu` checks `scripts/menu` against a stand-in shell (a copy of `sleep` named `quickshell`) that plays the shell's part in the request directory: usage errors, a missing or dead or foreign shell, a spool open to others, the input cap, choose, blank and last lines, cancel, the default app name, two clients at once, a stopped shell (exit 3), a caller killed with SIGKILL, and that no choice ever appears in an argument or message. The queue and the search are covered by `tst_MenuQueue.qml` and `tst_MenuSearch.qml` in `make test-qml`.

`make test-menu-session` and `make test-menu-stress` run `tests/menu/session-check` and `tests/menu/stress-check` against the real shell in a disposable nested session (private runtime directory) through `tests/scripts/run-menu-session`; each prints the failing lines, the counts and the kept artifact directory (`exec.log` holds the result). `session-check` starts two apps and checks `.shell`, the spool mode, that the card and scrim map, that a killed client's request is removed and that the card unmaps after its leave animation. `stress-check` runs a burst of 60 clients over 8 apps killed forward, backward and shuffled; 150 start-and-kill cycles with different gaps; 25 hand-overs polled every 20 ms for 0.4 s to prove the card never closes between two queued requests; malformed request directories (bad name, bad JSON, missing files, wrong types, dead pid, a plain file); odd input (empty lines, CRLF, invalid UTF-8, a 200 kB line, markup and shell syntax, a NUL byte, 100000 lines, 8 MB); the input cap; and that the shell stays alive and logs no menu warning. No input is injected, so choosing and cancelling are covered by `tst_MenuQueue.qml` (open follows the waiting requests, 400 random operations checked against a plain model, 1000 queued requests) and by hand. `session-check` also checks that the private home got the `uuctl` entry pointing at the staged `scripts/menu`; `make test-menu` checks `tools/scripts/seed-menu-entry` (Exec line, existing entry kept, no uuctl, path with a space, argument count). It also runs `launch-check` (`uuctl` started like the shell launcher does, including behind a shim that exits, must keep its card) and `close-check` (Enter and Escape sent with Hyprland `send_shortcut` answer two requests; afterwards no request directory, pipe, helper process or mapped window is left).

`make test-clipboard` checks `scripts/clipboard` with stand-ins for `cliphist`, `wl-copy` and `pgrep`: every state, the list JSON, copy, delete, wipe, image, a changed entry (exit 3), a timeout (exit 5), the size cap (exit 6), copy-content (what it copies and every refusal, exit 7), and that clipboard content never appears in an argument or message. The search logic runs in `make test-qml`. The panel itself is checked by hand: `make dev-seed-clipboard`, then Super+V.

`make test-notifications` runs a bounded nested session: the real notification server and popup windows, with `notify-send` sending a normal notification, an in-place progress update (`-p` then `-r`), a 100-notification burst, and do-not-disturb. It asserts newest-wins, one popup, unread counts and clearing, and, with a real foot window open and focused, that the popup layers stay `popupWidth` wide and leave foot's focus, size and position unchanged. The drawer stack is exercised in a hidden item (counts only), so no test window other than foot is mapped. `make test-notify` sends the same cases (plus urgencies, actions, long body, `image-path`, `image-data`, `sound-name`, `sound-file` and `suppress-sound`, `redaction` and `redaction held`) to a session you are watching; `NOTIFY_CASE_PAUSE` (default 1 s) sets the pause between cases. `make test-notify` on a terminal prints a numbered menu and asks which cases to run (numbers, ranges like `3-5`, `all` for every case that does not fake a recording, `everything` for all of them); the same selection can be passed as arguments (`make test-notify CASES='17'`). Without a terminal the plain cases run. The cases that fake a recording (`redaction`, `redaction held` and the rules cases) blur every notification, so they run only when picked by number. `redaction held` keeps the spoiler on and the notifications from expiring until Enter (or `NOTIFY_HOLD` seconds without a terminal) so the shader can be judged. The rules cases (`blur only app`, `blur only app regexp`, `reveal by app`, `reveal by app regexp`, `reveal by text`) test what a recording blurs per rules: `blur only app` and `blur only app regexp` blur just the named apps (a rule with no action, then a last `appMatch: "."` rule with `reveal: true` for the rest); the `reveal` ones blur everything but what a rule exempts. The shell reads its rules once, at start, so each case runs twice: the first run installs a marked rules file and asks you to restart the shell under test, the second sends one notification per app (blurred ones and readable ones, named in the output) and removes the file. They never overwrite a rules file of yours, and find the file through the runtime of the shell that owns the notification name, so they work in `make test-env` and `make test-env-host` (host mode writes under `.test-state/host/config`, not your real config). The image cases need a person to press Load image; the sound cases need to be heard.

`make test-launcher` remains a separate native dry-run check: it covers catalog and panel behavior, search focus, candidate selection, icon visibility/empty image source, failure presentation and four opens/closes with one retained panel. Contextual popup and scoped-settings cases retain their diagnostic frames. Non-graphical `make test-sandbox`, theme import, and this dry-run fixture do not expose the manager proxy.

The automated launcher check uses real `app2unit --test` from the configured PATH: it verifies desktop-entry filename handling, quoted arguments, `%c`, and the service-mode systemd command without starting an application. This does not prove real user-service creation or terminal launching. `xdg-terminal-exec` is required by app2unit for terminal entries. `test_icon_theme` declares the sandbox icon theme explicitly via `QS_ICON_THEME`; no host Qt configuration is mounted. Diagnostics include `launcher-test.log` and `frame-launcher.png`.

`make test-app2unit` runs `tests/scripts/check-app2unit-scope` as a standalone retained smoke test; it is not part of `test-env` or the launcher GUI check. Host-side app2unit registers a uniquely named scope and slice, then its command enters Bubblewrap. The application has private HOME, XDG directories, session D-Bus, PID, mount and network namespaces. No host manager socket or host session bus is mounted inside. The check verifies the host manager environment is unchanged and that run-owned units and tagged processes are gone. `test_app2unit_seconds` explicitly bounds the run. There is no private UWSM or journald setup. Registering before entering the private PID namespace avoids the direct manager-socket failure (`No data available`) observed with a hidden host peer. This is trusted development isolation with read-only installed system files, not a VM. `make test-launcher` remains a dry-run for app2unit and does not start an application.

Launch-progress checks delay the configured real runner only in the private fixture. They capture `frame-launcher-starting.png`, verify one row-local pulsing dot and no visible Starting footer, and compare panel/search/list/row/label bounds while pending. Error presentation preserves the card height; successful handoff closes once and reopening has no stale indicators. The test timer rejects nested ticks during native keyboard event processing.

`make test` also covers AppSearch ranking/filtering/reindexing with a nongating 1,000-entry timing diagnostic. `tst_LauncherOutput.qml` runs against the explicit default, a generated named-output override, and a generated index override. It verifies exact-target resolution and refusal to substitute an unavailable output; invalid renderer input must preserve the prior policy. Generated changes remain inside the writable test copy, and the host launcher-output file is protected by the before/after hash check.

## Keeping a test wallpaper across restarts

### Try every reference Theme

```sh
make test-import-themes      # import palette definitions; profile recipes stay unchanged
make test-env                # nested session only, with popups closed
# Alt+Multi_key+W, choose a wallpaper, Enter, then select a palette definition.
# Ctrl+Enter saves the recipe and activates its complete generation; Alt+Multi_key+Escape exits.
make test-env                # inspect the retained wallpaper/theme after restart
```

The high-level importer uses the configured runtime command roles and `paths.themes`.
It converts each reference variant to one flat `config.ini` at
`themes/SLUG-VARIANT/config.ini`. Imported definitions contain palette colors only. Import creates no
profile recipe, selection, or activation. The picked
wallpaper remains a draft until final Save and apply.

`tests/nested.conf` explicitly owns `test_theme_reference`, plus
`test_theme_positive`, `test_theme_warning` and `test_theme_negative` source
fields. Their defaults are `refs/100-themes`, `green`, `yellow` and `red`. These are declared mappings, not
guesses about terminal-color semantics; review previews before applying.
Theme definitions persist under private `themes/`; profile recipes persist
under private `profiles/`. Import never changes the active profile or live desktop.
Retries regenerate matching reference definitions, replacing local edits to those IDs when reference output differs. Unrelated/custom Theme IDs and all profile recipes remain unchanged. References are mounted read-only.
Import is an explicit step, never ordinary startup or an automated UI side effect.

### Restart or reset private state

```sh
make test-env           # nested session only; open the picker on demand, exit with Alt+Multi_key+Escape
make test-env            # same private home/cache/choice, latest project code
make test-env-snapshot  # bounded restart, capture frame/logs, close automatically
make test-env-clean     # reset private choices/cache; keep Theme definitions; host/source untouched
```

The default storage is `.test-state/nested/`: `home/` owns its `.config`, `.cache`, and `.local`. The private `.config/ui-shell/settings.ini`, Theme definitions, schema-2 profile recipes and scoped settings survive. Each recipe records wallpaper selections and full palette data. The first persistent run seeds the manifest, clean default seed, and absent default Theme/profile stores. Subsequent `test-env` runs retain those choices and reusable compiled cache generations while staging fresh code. Targets choose their state mode explicitly; the direct nested helper's configuration default remains ephemeral. Automated checks use ephemeral state so scripted changes do not overwrite interactive choices.

Persistent sessions mount the private configuration **directory**, so Save and apply can atomically replace `settings.ini` and retain standalone `profiles/`. `test_ephemeral_config_parts` overlays fresh `scripts/`, `shell/`, and `hypr/` directories for each run. The host home remains unavailable; saving needs no relaxation of isolation.

The picker and editor retain wallpaper and palette choices as a draft. Advancing, loading a saved profile, Back, or cancelling must not change live wallpaper, saved selections, active palette, or persisted profile; only final Save and apply commits the bundle and refreshes colors. Reopening the persistent session restores the selected bundle and regenerates QML from retained inputs/cache. `shell-palettes.log` records startup output palettes, `global-palette.log` the startup global palette and `wallpaper-startup.log` the native assignment. A display override changes that display's QML palette; wallpaper-mode global colors still follow `palette_source` in `hypr/default/monitors.lua`.

Cleaning resets private choices, generated profiles, component settings, cache and other private home state, then immediately reseeds the source manifest, replaces `default/` with the clean seed, and creates missing default Theme/profile stores. It reads the saved manifest's Theme storage address without loading the selected profile; stale profile selections do not block reset. Every Theme definition is retained byte-for-byte, including imported definitions and user edits. If storage was renamed, the retained definitions move to the source-default Theme directory. Retained definitions take precedence over checked-in palettes; reset never validates or regenerates them. Cleaning does not remove project configuration or retained diagnostic artifacts. Storage is restricted to `.test-state/<profile>` and carries an owner marker. A sibling lock prevents simultaneous sessions and cleaning while a session is active; the harmless lock file remains after cleaning. Missing or redirected manifest/Theme storage fails before existing state changes.
